Every run script listed below passes -deadlock, which turns off TLC's report of a state with no successor, a terminal state. Each line is one module at one set of constants, unmutated, through a wrapper that EXTENDS it and adds only definitions, so the state graph is the module's own. TLC runs with its own deadlock check on, which reports a reachable state with no successor (Terminal == ~ENABLED of the specification's next-state relation), and, where it reports one, checks INVARIANT TerminalAtBound (Terminal => AtBound, the bound being the module's own end, as the line names it). A line claims that at its constants every terminal state is at that bound, or there is none, so that the flag turns off the report of the module's end and hides nothing else. It claims nothing at other constants, where an end can fall elsewhere, or under a mutation, whose rows may stop anywhere and need only reach their counterexample. Nor does it claim that the module never stalls: a state whose only step leaves it unchanged has a successor, for ENABLED as for TLC's check, so neither sees it.

The scripts that pass -deadlock but are not model-checking runs of a transition system, with their reason:
  mechanism-trace-run.sh (sha256 c4aa304816abfab3), and mechanism-trace-results.sh (sha256 31cc06e01ae16523), which runs it: a replay of one recorded trace through Mechanism.tla (sha256 e29dbaf0936dbae1) by TraceSpec, whose next-state relation is TraceNext == TraceStep \/ Done. TraceStep is enabled at every step before the trace's end, and Done == i = Len(Trace) /\ UNCHANGED vars is a step at the end that leaves the state unchanged, which TLC counts as a successor. So a replay has no terminal state and the flag is inert: the replay ends at the trace's end by design, but by stuttering there, and Done is what keeps TLC from reporting that end as a deadlock.
  paxos-trace-run.sh (sha256 c494c6a147a771f9), and paxos-trace-results.sh (sha256 86fa3fb79d6bd439), which runs it: a replay of each recorded run of the reference's replicas through Paxos.tla by PaxosTrace.tla (sha256 63a086605dca3cad), whose TraceNext == TraceStep \/ Done. TraceStep needs only Pending (i < Len(Trace)) and an event of one of the seven kinds, each of whose disjuncts only assigns: whether the event could be given (a message received was sent, a forward was in flight, an election was a non-leader's) is the invariant TraceReceivable, not a guard, so an event the model would refuse is reported as a violation, not left as a state with no successor. An event of any other kind leaves TraceStep disabled, but before that TraceStateMatches evaluates EventCtx of it, a CASE with no arm for it, and TLC stops with an error, which the script prints as ERROR. Done == ~Pending /\ UNCHANGED tvars is the stuttering step at the trace's end. So a replay has no terminal state and the flag is inert, as for mechanism-trace-run.sh.
  simulate-run.sh (sha256 82ba955a0c94e8c3): TLC's simulation mode, which draws behaviours at random, each to -depth. Where a behaviour reaches a terminal state the flag ends it there and the next is drawn; without the flag the first terminal state any behaviour reaches stops the run with "Deadlock reached", so in a module that ends at its bounds the first behaviour to end would stop the run. The flag is needed for that. It runs at constants exhaustive checking cannot reach, which no line above covers, so where its behaviours end is not checked, and a NO ERROR SAMPLED line says nothing about it.
