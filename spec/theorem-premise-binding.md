# Theorem-to-premise binding

**2026.09.30**, revised 2026.10.01 (Batch 24: T-0045-14), revised 2026.10.02 (ADR-0046, Batch 25: the proofs; four "Breaks under" corrections and one parameter premise struck), revised 2026.10.02 (the launcher in the node: four confinement rows and trace validation, **pending** ADR-0033 A7; `inventory.py`), revised 2026.10.06 (ADR-0053, Batch 36: the Lean route; derived premises, so that a proved row rests on `invariant(M)`; `refines(Seats)`) · the table ADR-0045 §3 owes and ADR-0023 §2 assumes · DRAFT, revised with the records it binds

**What this is.** One row per checked property, naming what it rests on: the trusted-base rows (`T-0045-n`, ADR-0045
Annex A), the degeneracy parameters (ADR-0023 §6a values), and the gaps the corpus has declared and not closed. A
property **holds for a deployment** when every row it names is declared in that deployment's trusted-base
declaration as *delegated* or *trust root*, every parameter premise holds, and no gap premise is false for it. An
**excluded** row, an undeclared row (ADR-0045 §3, rule 1) or a refused component makes the premise false and the
property **void** for that deployment. That is ADR-0023 §2's inventory, theorems minus those whose premises are lost,
computed from this table instead of listed by hand. The last column computes it for the reference, against
ADR-0045 Annex B.

**What this is not.** A proof by itself. Every property here was checked by TLC at small constants, or restated as
a test, by the same hands that wrote the records (every checkpoint's §8), and the invariants of thirty-seven rows
are also proved, under the hypotheses the "Breaks under" column names, by the proof module the *Checked in* column
cites (ADR-0046), by the same hands. A row says what a check or a proof *assumed*; it does not strengthen either.

**Premises every row shares (BASE).** T-0045-1 (the replicas apply the ordered log as crash-fault machines),
T-0045-11 (the records are the records that were ratified), **T-0045-28** (the running code refines the checked
specification: no refinement exists, so for any running deployment every property below is conditional on this
row), T-0045-29 (TLC, at the constants run) and T-0045-30 (the build toolchain). They are not repeated per row.
**For a property whose *Checked in* column names a proof module** (ADR-0046), the invariant rests on
**T-0045-31** (the prover) in place of T-0045-29, for every constant the proof module's named assumptions admit, and
its hypotheses are the "Breaks under" column; the mutations and witnesses rest on T-0045-29 as before. Where the
proof's hypothesis and the TLC rows disagreed, the column was corrected on 2026.10.02 and the row says so. **Since
Batch 36 (ADR-0053) that is a derived premise**, `invariant(M)` for the proof module M: T-0045-31, or T-0045-37 and
M's Lean encoding faithful, `enc-faithful(M)`. A proved row's premise cell names it in place of T-0045-29, and the
two `Seats` rows name `refines(Seats)` in place of T-0045-28 (*Derived premises*, below). A property whose *Checked
in* column names a Lean file is also proved in Lean, of that file's encoding, on T-0045-37.
Properties named `Never…` in the results files are reachability witnesses that must be *violated* (the non-vacuity
convention, G2 §3) and are not theorems; they are omitted here.

**Parameter premises** are written as the archetype value, with the degeneracy that falsifies them in brackets.
**Gap premises** are assumptions no row and no parameter carries: the corpus has declared them open.

**Reading the last column as an inventory.** At the reference, every theorem premised on confinement, gate evidence,
hermeticity or channel fidelity is void; the routing theorem and the gate verdicts rest on checked proofs since
2026.10.01, where before they were the solver's assertion; the bundle's revision is a file name; the reach bound is declared and not enforced. What remains holds of
the modules and, by trace validation, of the running code on every tested path: the lease, the fence, revocation,
composition, the rules floor, the bootstrap pair, seats, any-of, coupling with its collusion gap, Run's counters and
seal. That is ADR-0045 Annex B's inventory sentence, computed.

**As a matrix** (2026.10.03). The table is a Boolean incidence matrix, theorem row × premise, and a deployment's
inventory is *holds = ¬(B · ¬d)* for its declaration *d* (`derived/topak-rung-DAG-as-matrix-2026.10.03.md`).
`spec/theorem-premise-binding.json` is that matrix: this table's T-row premises per rung, sparse in the rung (four
rows change with it), and the parameter, condition and gap premises as columns with the degeneracies that falsify
them. `spec/inventory.py` evaluates a declaration against it, and `inventory.py --check` fails when the JSON's T-rows
and this table's differ at any rung. This table stays canonical for its rows; the JSON's other columns are a
transcription of the column before last, and are not checked against it mechanically. Since Batch 36 the JSON also
holds the derived premises and each theorem's replacements; `inventory.py --check` checks that every derived premise
is defined, acyclic and monotone, and that this table's "T-0045-n as `name`" notes are the JSON's replacements.

**Keeping it current.** A new property adds a row; a new T-row or degeneracy adds a premise; an ADR-0033 addendum
that changes a row's class at the reference changes the last column. A change to a row's premises changes `spec/theorem-premise-binding.json` in
the same commit, and `inventory.py --check` passes before it lands. `tools/check-refs.py` does not read this file;
the archetype-evolution record (G6 item 7) owns its versioning and the rule for a premise edge added into an existing
theorem, which weakens the theorem and needs its own record (ADR-0023 carried scope).
