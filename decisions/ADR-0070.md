## Decision

### 1. Every boundary declares seven things, and a boundary with no instant is a finding ⟨K2⟩

A boundary is declared by:

1. **Its sides.**
2. **What may cross**, typed.
3. **Its instant**: the event at which the crossing is checked.
4. **Its interval of untruth**: how long the boundary's claim may be false.
5. **What happens if the check cannot run.**
6. **Its adversary**: who is assumed to attack it, named against TM1 to TM14 (ADR-0068) where one fits.
7. **Its owner**: the record that decides it.

Items 1 to 5 are the register's columns. Items 6 and 7 are the two its assessment found missing *(drafter's choice)*.

**Orientation.** A crossing that adds authority, reach or trust has an instant at which a quorum, an issuance or a
promotion decides it. A crossing that subtracts is local, needs no quorum, and may run on a local monotonic clock
(ADR-0032 §2). **A boundary with no instant is not a control. It is a finding**, entered in §12 or the review's
register, and carried until an instant exists.

### 3. Every production target artifact has a build-side check, a boundary check, run checks and an end ⟨K3⟩

**The artifacts.** These are the kinds the records name as crossing B1 (ADR-0024 §1 and A3; ADR-0035 §4; ADR-0054,
Proposed), plus the two that reach Run without promotion (the genesis bundle and anchor issuances).

**The common rule, for every row** *(drafter's choice)*:
- **(a) Hermetic build.** The artifact is built in a Build round from pinned inputs, by allowlisted tools only (ADR-0022
  §3), so its sealed topic-set digest is its provenance (ADR-0021 §4).
- **(b) The bytes are signed.** The digest that is signed and voted on is the digest of the bytes the mechanism will
  load. It is not a source digest, a revision string or a file name. The load recomputes it (finding F1).
- **(c) A bill of materials.** The artifact carries an SBOM, which the gate projects from the round's `consumed` set
  as ADR-0035 §1 projects lineage. An authored SBOM is a cross-check, and a divergence is *Contested*.
- **(d) Code is rebuilt.** An artifact that is code is rebuilt by a second builder on a second toolchain, and the
  digests must match (§6).
- **(e) A declared end**: expiry, revocation or retirement.

### 4. Phase 1: the trusted base for standing up Build is evaluated before the first round, and every row is identified before it runs ⟨K1⟩

1. **A stand-up declaration precedes the first Build round** of any deployment, and of genesis *(drafter's choice)*.
   It instantiates ADR-0045 Annex A and §10's rows. For each row it records how the row's identity was fixed, and how
   that was checked on the host where it runs.
2. **Nothing third-party runs before its full SHA-256 is checked** against a digest the corpus tracks. That covers
   tools, toolchains, crates, container images and Lean and Lake dependencies. A 16-hex prefix is a label, not a
   check. A floating reference (`:latest`, an untagged image, a pre-release tag GitHub rebuilds) is refused.
   - **The design argument.** Before the check, the download channel is a trust root, since a substituted tool can
     claim "checked" or "proved". After it, a substitution can only be refused. **The full-digest check moves the
     channel from trust root to delegated** under ADR-0045 §2, and that is why it is required rather than
     recommended.
3. **Every platform that runs a pinned tool has its own pin.** The Lean pin is arm64-darwin only (ADR-0053 Open
   obligations). A run on another platform under that pin is unpinned.
4. **What enforces a pin is measured.** The install scripts and the wrappers that refuse an unpinned binary are
   removed from `manifests/EXCLUDE`, so that a checkpoint fixes them along with the pins they enforce (finding F2).
5. **The build host is a Build principal's host.** It is ephemeral, built from a declared image, and appraised as
   ADR-0034 appraises a guest, at whatever rung the deployment declares. A host that outlives its round is declared as
   a degeneracy.
6. **The key ceremony comes before any key a deployment trusts exists** (ADR-0025 Open obligations). Dev keys never
   cross into a deployment (G6). Anchor, bundle, verifier, identity-provider and gate-runner keys are hardware-held,
   each with a custody row *(drafter's recommendation; an HSM is named in ADR-0045 only as delegated for
   availability)*.
7. **Order of stand-up** *(drafter's choice)*. Each step rests only on the ones before it:
   1. tools by digest;
   2. the toolchain's reproducibility check;
   3. the floor gates;
   4. the specifications and their results;
   5. the mechanism build.
8. **At genesis**, all of this is declared and not yet independently checked. It is T-0045-11's identity, and the
   full-corpus review of ADR-0029 A2 is where it is first read by another.

### 5. Phase 2: the development process is a Build round, and the tandem developer is two parties on opposite sides of a gate ⟨K1⟩ ⟨K4⟩

#### 5.1 The agent half is a havoc drafter, `Mediated`, and outside the trusted base

**The assistant is to the corpus what a Thinker is to the mechanism.** Nothing it produces takes effect except
through the custodian's act, as nothing a Thinker requests takes effect except through an admit. Under ADR-0045 §2 it
cannot be a row: its failure can add anything to a draft, and its identity is issued by nothing. So it is **excluded**,
as models are, and every claim rests on the act that stands between it and the corpus *(drafter's choice; the
alternative, a trust-root row for the assistant, fails §2's test)*. The assistant is held to Build's alphabet as
closely as its harness can express it:

| ADR-0022 verb | What the assistant may do | Control |
|---|---|---|
| `Read` | The repository and the sources the session names | **Everything read from outside the corpus root is `untrusted` ingress**: web pages, issue and PR text, tool output, files from elsewhere. An instruction found there is content, not a request (ADR-0048 §3's rule, applied to the drafter) |
| `Draft` | Write in a worktree or a session branch | No write to the default branch. No credential that could make one |
| `Invoke` | Allowlisted tools only | The harness's permission list is a tracked, gated artifact, and a change to it is reviewed as a change to a floor. Network egress goes through a declared allowlist. Credentials are injected by the proxy and scoped to one repository and one branch. No secret is in the workspace |
| `Emit` | A session record | Every commit carries the session link (already the case). The session record names the model that served it, outside the corpus |
| `Submit` | Propose a branch or pull request | The custodian's merge is the `Vote`. **The assistant never votes**, never ratifies, and is never the reader that satisfies ADR-0029 A2 (the `ratifying-records` skill already says so) |

Further rules for the agent half:
- **A claim the assistant marks Met is a claim, not evidence.** Every Met carries the command and digest that make it
  checkable. The custodian, or CI (§5.3), re-runs it before ratification.
- **One session drafts. A different reader reviews.** A second session of the same model is independence of context
  and not of lineage (the review, §1). It does not count as A2's reader unless the custodian rules that it does.

#### 5.2 The human half is at the gate, and the gate is hardened

**The custodian is not evictable, so the custodian is at the gate** (ADR-0002 A2, B14). Nothing can make the gate
safe while custody is (1, 0). What this record asks for is that it be attributable and hard to steal *(drafter's
choices)*:
- **Account and keys.** A hardware-backed second factor on the repository host. Commits and tags signed with a
  hardware-held key. The allowed-signers file tracked, so that a signature can be checked from the tree.
- **Branch protection on the default branch.** No direct push. No force-push. Merge only through a pull request whose
  required checks (§5.3) have passed. As ADR-0069 §9 C-2 has it, a carrier's checks may refuse and never admit.
- **Ratification is a tagged act.** A Batch is a signed tag over the merge commit. The tag, not the merge, is the
  ratification's instant.
- **The custodian's own environment is declared.** It is part of T-0045-11's identity: which machine ran what, and
  that machine's toolchain, recorded in results files as they already are.
- **The residual.** At (1, 0), one compromised account is a compromised corpus. That is T-0045-11's failure as it
  already stands. The bootstrap's custody (ADR-0029, at least five humans) is what removes it, and nothing here does.

#### 5.3 Gates before release run on every change and fail closed

**The development gates run in CI on every pull request** *(drafter's choice; the alternative, gates run by hand at
each Batch, is today's practice and CR-57's finding)*. They are:
- `tools/check-refs.py`, the record lint, `tools/verify-manifest.sh --all`, the drift test, `spec/proof-sync.sh` and
  `tools/lean-sync.sh`;
- the floor gates and `cargo test`;
- a dependency audit against an advisory database, and a review of each new crate or version;
- secret scanning;
- SBOM generation and a reproducibility check of the mechanism build (§6).

ADR-0069 §10.2 repurposes f1-tla's workflows as this repository's carrier. §10.3 makes them evidence for the
custodian's ratification during genesis. Which of the checks above those workflows run was not read for this draft.
This section asks for all of them, under the rules below.

Three rules govern them:
- **Each checker fails closed.** A checker that passes on an empty input, or skips silently, is a defect (CR-57). Each
  checker carries a planted-defect test that must fail.
- **Gate evidence is signed by the gate runner** under a key issued under ADR-0025 §1 (f). That is the condition on
  which T-0045-13 stops being excluded (ADR-0045 §6). Until then, evidence is an operator's assertion, as it is today.
  ADR-0069 §6 G-1 and G-2 decide this, and this record cites them.
- **Pace is bounded by review** *(drafter's recommendation)*. While a checkpoint is owed, or more than an agreed
  number of records stand Proposed and unread by anyone but their drafter, new drafting waits. This is the review's
  first remedy for CR-61 ("Cut G12 before drafting anything else"), written as a stall. It is the custodian's choice
  whether to adopt it, and what the number is.

### 6. Phase 3: promotion to production keeps ADR-0024's quorum, and binds it to computed provenance, loaded bytes and a staged reach ⟨K1⟩

1. **ADR-0024 stands**: a unanimous grant quorum, veto seats, author recusal, and a vote bound to (artifact digest,
   gate-evidence digest, rules epoch). Nothing here lowers it.
2. **Provenance is a projection, for every artifact.** ADR-0035 makes Persona lineage a projection of the Build log
   because "a gate over manifests checks what the author claims". The same holds of every artifact's provenance and
   bill of materials, which are projected from the sealed round (§3 (a), (c)) *(drafter's choice; this generalizes a
   Proposed record, and stands or falls with ADR-0035 §1's method)*. In SLSA's terms, the provenance is generated by
   the platform and not by the tenant.
3. **The signature binds the bytes that load** (§3 (b)). For a bundle, the signed digest is over the tarball's
   `policy.wasm`, `data.json` and `.manifest`, and the mechanism recomputes it at load. ADR-0069 §7 S-1 has the
   signing stage recompute the digest from the bytes. The recomputation at load is what this record adds, and it is
   where F1 is.
4. **Code is reproduced before it is voted on.** Two builders, on toolchains from different sources, produce the same
   digest, or the promotion stalls. This answers T-0045-30's residual as far as the two toolchains are independent,
   which is the diverse-double-compiling argument, and no further. **A grant seat reads the second builder's
   evidence**, which is evidence not derived from the author's artifacts (A4). ADR-0069 §6 G-4 finds that mechanism
   code has no gate of its own, and that it cannot promote until a record gives it one. This is that gate.
5. **Reach is staged** *(drafter's recommendation; the CrowdStrike scenario's `proposed:StagedPromotion`)*.
   - A promotion's reach is a field of the tally. It advances ring by ring, and no ring is reached until the previous
     ring's bake-in has passed without a finding.
   - **A finding may stop the advance, and never cause it** (ADR-0007).
   - The bake-in is counted in rounds of the ring, because an advance adds reach and ADR-0032 §2 gives a local clock
     only to intervals that subtract.
   - The scenario's reason: "A unanimous quorum of reviewers who all trust the same validator adds nothing here".
     Staging does not depend on the reviewers being right.
6. **Distribution fetches nothing at runtime except by digest.** The mechanism refuses an artifact whose digest is not
   in the promoted set under the current rules epoch (ADR-0027 §1, ADR-0030 §3). Freshness is the rules epoch, which
   is a log position and not a clock.
7. **Retreat is a revocation, and return is a promotion.** Revoking a promoted digest subtracts. It is local and an
   operator's (ADR-0031 §5). Going back to an earlier artifact is a promotion like any other, because it adds the
   earlier artifact's reach back.

### 7. Phase 4: the runtime secures each artifact for its whole life, and a response that subtracts never waits for a quorum ⟨K1⟩ ⟨K3⟩

1. **The runtime records stand** and are not restated. They are:
   - the lease as the composite credential (ADR-0031);
   - attestation at grant, with a guest per round (ADR-0034);
   - fencing without a clock (ADR-0032);
   - decide, then order, then re-check at apply (ADR-0015 E1);
   - Observer coupling (ADR-0039);
   - the forensic floor (ADR-0028);
   - break-glass as an emergency seating (ADR-0052).
2. **Every promoted artifact has a declared end** (§3 (e)). An artifact with no expiry, no revocation path and no
   retirement event is a finding.
3. **An advisory becomes a revocation.** When an advisory, a finding or an upstream notice names a component in a
   promoted artifact's SBOM, the operator revokes that artifact's digest. This is a targeted revocation: local, with
   no quorum and no peer (ADR-0031 §5). The fix comes back through the full promotion. Because the revocation
   subtracts, it needs no trusted time, and nothing in it waits for a vote.
4. **Invariant monitors** *(drafter's recommendation; ADR-0057 §11 lists runtime monitors as a "Could")*. For each
   proved module whose invariant is over facts the correlator reads, the correlator carries a fold that checks the
   invariant on the live log. Under ADR-0051 its finding may only subtract.
5. **Key rotation and compromise.** Rotating a key the mechanism trusts in place of its own check is an issuance
   (ADR-0025 §1 (f)). Responding to the compromise of one is a revocation of what it vouched for, followed by an
   issuance. The first part needs no quorum.
6. **Before any deployment, not at the reference**, two things are preconditions:
   - replicas are mutually authenticated (B15, A9);
   - the operator channel carries a signed action (B16).
7. **`W` and `L` are measured** in every deployment that declares a `T_irrev` (ADR-0032 §4). This gives B26 an instant.

### 8. Phase 5: Run reaches Build only as a deny, or as labelled, erasable ingress admitted to a corpus root, and nothing Run originates enables a Build act ⟨K1⟩

**Run reaches Build in three ways, and no other** *(drafter's choice)*:

1. **A deny.** A Build-domain Observer or correlator finding is ground for `Vote(deny)` at a veto seat (ADR-0038 §6,
   ADR-0051 §3), or for a revocation. This is in force today.
2. **Evidence.** Recorded traces enter the specification graph's runtime layer (ADR-0057 §1, Proposed) at the grade
   of their edge. They are evidence about a module and never a premise of an admit.
3. **Ingress**, by ADR-0069's intake (its §3 to §5). A corpus-root revision is promoted under ADR-0024. A `source:
   run` object is computed from the log and never written, and its `generatedBy` is projected (RR-1). Payloads and
   labelled items are admitted only once Build labels, and erasure follows the data (LR-1 to LR-3). This record does
   not restate those rules.

**Nothing Run originates enables a Build act.** ADR-0069 §2 says so. This record gives it ADR-0065 §1's form, so
that a module can state it. For every Build admit
and every promotion, the same request with every Run-originated item removed must still be permitted. Run intake may
inform what a person drafts. It never satisfies a gate, fills a vote, or stands in for evidence the grant seats
require.

**The adversary is TM1, writing its own future training data.** A Thinker that can shape its Reports can shape
intake. ADR-0069 §4 states the same residual: its rules make that influence "visible and attributable", and "Nothing in
them makes it harmless". An evaluation suite built from intake is "a Build artifact with its own lineage record"
(ADR-0035), and it may only refute.

### 9. Phase 6: improvement is a loop with an instant at each step, and a finding closes only when a check that would have caught it exists ⟨K1⟩

| Step | What happens | Instant | Rule |
|---|---|---|---|
| **Detect** | Observer and correlator findings; dependency advisories; scenarios and simulations; dated reviews; SECURITY.md reports; upstream reports (ADR-0058 §6); a checker's failure | The finding is recorded | **A finding may only subtract** wherever it acts at runtime (ADR-0007) |
| **Register** | Each finding gets exactly one row in one register, with a severity, an owner record and the boundary of §2 it is against | The row exists | The review counts 108 findings "carried by no list" (CR-60). A finding without a row is lost |
| **Contain** | If the finding is against something running: a revocation or an epoch fence, at once | The revocation is ordered | Subtraction needs no quorum and waits for none (§7.3) |
| **Disposition** | Applied, declined with reasons, or carried as named debt (ADR-0029 A2's three) | The disposition is written | Silence is not a disposition |
| **Act** | The typed act its status allows: an erratum, an amendment, an R-revision, a new record, a new release | A Batch, or a promotion | Accepted text changes only by History row |
| **Prove it closed** | **A check that fails on the defect and passes on the fix**: a TLC mutation, a planted-defect test, a floor test, a regression case | The check is in CI | **A finding closes only when such a check exists** *(drafter's choice)*. A finding with no possible check is carried as debt, not closed |
| **Re-cut** | Pins, manifests and the checkpoint | The cut is signed | §5.2 |
| **Re-read the boundaries** | Each record names the rows of §2 it touches, and each checkpoint re-reads the inventory | The checkpoint | A new boundary that no row names is a C2 finding against this record |

### 12. Findings

These were found while drafting. Each is reported, and none is fixed here.

- **F1. The bundle signature binds a source digest and not the bytes that load.**
  - `build-bundle.sh` (`4993cc2a703b6838`) computes the revision as a SHA-256 over the Rego sources and `data.json`
    (:19-20). It compiles the Wasm with the untagged `openpolicyagent/opa` (:22), and signs `{"revision": R}` (:26).
  - `topak-bundle` (`beefb4c24d95dd9f`) reads R from the tarball's own `.manifest` (:143-144). It verifies the
    signature over `bundle_body(R)` (:57-58, :189), and loads `data.json` and `policy.wasm` (:208, :212) without
    recomputing anything against R.
  - So a tarball whose `.manifest` names a signed revision loads whatever Wasm and `data.json` it carries. ADR-0044's
    Consequences claim the artifact is trusted "by a digest a key vouches for, not by a name". The manifest's revision
    is a name inside the tarball.
  - `data.json` carries the allowlist. **Whether a substituted `data.json` can add a tool within what the floor
    permits was not assessed here.** Under SECURITY.md this is a safety finding: a divergence between the reference
    and its record that a reader would not notice.
- **F2. What enforces the tool pins is not measured.** `manifests/EXCLUDE` (`0584c9a148c566a9`) excludes
  `tools/install-*.sh`, `tools/tlapm` and `tools/tlc`, the scripts and wrappers that fetch the tools and refuse an
  unpinned one.
- **F3. No CI on this tree.** At `981bc77` there is no `.github/`, and every gate in §5.3 is run by hand. ADR-0069's
  branch carries workflows repurposed from f1-tla. Its Status note says they are green on pull requests into that
  branch, and not yet on `main`. At this tree the drift pins fail on ADR-0054 and ADR-0055, whose bytes have moved
  since they were pinned, and nothing ran to say so.
- **F4. The gate's own boundary fails ADR-0045 §2.**
  - The repository host's access control (T-0070-2) can add, and its identity is issued by nothing.
  - 105 of 150 commits are unsigned. The 45 signed ones were made by GitHub.
  - At genesis this is inside T-0045-11's declaration. After bootstrap it needs an issued key (T-0070-3) or it is not
    a row.
- **F5. Nothing in Annex A names the bundle compiler** (T-0070-5). T-0045-6 covers OPA at evaluation and not at
  compilation.

## Consequences

**Positive**
- **One inventory, seven columns, and every hole visible.** B18, B19, B22, B24, B25 and B26 have no instant today,
  and the table says so in one place.
- **The tandem developer is placed on the pattern's own terms.** The assistant is a havoc drafter outside the trusted
  base, and the custodian's act is the gate. What makes that true is stated as A-0070-1 and A-0070-2, which can be
  checked.
- **A full-digest check moves the download channel from trust root to delegated**, which is the cheapest reduction of
  the trusted base available.
- **Every subtracting response (revocation, retreat, a finding stopping a ring) needs no quorum and no clock.** Every
  adding one (promotion, a ring's advance, a return, intake) has an instant.
- **Findings close on a check**, which addresses CR-60 at the point where findings are lost.

**Negative**
- **The trusted base grows by eight rows**, two of which fail ADR-0045 §2 as they stand.
- **Promotion gets slower**: a second builder, a staged reach, and computed provenance, which needs ADR-0035's method
  in force.
- **Everything in §5.2 is still one person.** At (1, 0) a hardened gate is still a single gate.
- **The record is wide.** It cites more than thirty records and owes entries in five records and the ToO, some jointly with ADR-0069. That is the CR-61 pattern this
  record also criticizes, and it is why §5.3 recommends a pace bound and the Options recommend a split.
- **One author, one day, and no deployment.**
