## Decision

### 1. Every boundary declares seven things, and a boundary with no instant is a finding ⟨K2⟩

A boundary is declared by:

1. **Its sides.**
2. **What may cross**, typed.
3. **Its instant**: the event at which the crossing is checked. ⟨R1⟩ An instant names the predicate checked there, and
   the evidence that shows the check ran. An event with no predicate is not an instant.
4. **Its interval of untruth**: how long the boundary's claim may be false.
5. **What happens if the check cannot run.**
6. **Its adversary**: who is assumed to attack it, named against TM1 to TM14 (ADR-0068) where one fits. ⟨R1⟩ That
   includes an adversary to what crosses being read, not only to its being changed.
7. **Its owner**: the record that decides it.

Items 1 to 5 are the register's columns. Items 6 and 7 are the two its assessment found missing *(drafter's choice)*.

**Orientation.** A crossing that adds authority, reach or trust has an instant at which a quorum, an issuance or a
promotion decides it. A crossing that subtracts is local, needs no quorum, and may run on a local monotonic clock
(ADR-0032 §2). **A boundary with no instant is not a control. It is a finding**, entered in §12 or the review's
register, and carried until an instant exists.

### 3. Every production target artifact has a build-side check, a boundary check, run checks and an end ⟨K3⟩

**The artifacts.** These are the kinds the records name as crossing B1 (ADR-0024 §1 and A3; ADR-0035 §4; ADR-0054,
Proposed), plus the two that reach Run without promotion (the genesis bundle and anchor issuances).

**The common rule, for every row** *(drafter's choice)*:
- **(a) Hermetic build.** The artifact is built in a Build round from pinned inputs, by allowlisted tools only (ADR-0022
  §3), so its sealed topic-set digest is its provenance (ADR-0021 §4).
- **(b) The bytes are signed.** The digest that is signed and voted on is the digest of the bytes the mechanism will
  load. It is not a source digest, a revision string or a file name. The load recomputes it (finding F1). ⟨R1⟩ Where
  more than one engine evaluates the artifact, as the bundle's sidecar and its in-process fallback do, each is held to
  the signed digest, not only the one the mechanism loads itself.
- **(c) A bill of materials.** The artifact carries an SBOM, which the gate projects from the round's `consumed` set
  as ADR-0035 §1 projects lineage. An authored SBOM is a cross-check, and a divergence is *Contested*.
- **(d) Code is rebuilt.** ~~An artifact that is code is rebuilt by a second builder on a second toolchain, and the
  digests must match (§6).~~ ⟨R1⟩ An artifact that is code is rebuilt by a second, independent builder from the same
  pinned toolchain, and the digests must match (§6.4).
- **(e) A declared end**: expiry, revocation or retirement.

### 4. Phase 1: the trusted base for standing up Build is evaluated before the first round, and every row is identified before it runs ⟨K1⟩

1. **A stand-up declaration precedes the first Build round** of any deployment, and of genesis *(drafter's choice)*.
   It instantiates ADR-0045 Annex A and §10's rows. For each row it records how the row's identity was fixed, and how
   that was checked on the host where it runs.
2. **Nothing third-party runs before its full SHA-256 is checked** against a digest the corpus tracks. That covers
   tools, toolchains, crates, container images and Lean and Lake dependencies. A 16-hex prefix is a label, not a
   check. A floating reference (`:latest`, an untagged image, a pre-release tag GitHub rebuilds) is refused.
   - **The design argument.** Before the check, the download channel is a trust root, since a substituted tool can
     claim "checked" or "proved". After it, a substitution can only be refused. **The full-digest check moves the
     channel from trust root to delegated** under ADR-0045 §2, and that is why it is required rather than
     recommended.
   - ⟨R1⟩ **And no further.** A full digest fixes which bytes run, not whether whoever published them was honest.
     The digest the corpus tracks is taken from a first download, so that download is trusted on first use, and an
     upstream compromise already present then is pinned faithfully. That compromise is B18's own adversary. Crates
     also run code at build time (`build.rs` and procedural macros). The publishers stay a trust-root row
     (T-0070-9), and the review of each new crate or version (§5.3) is what reads them.
3. **Every platform that runs a pinned tool has its own pin.** The Lean pin is arm64-darwin only (ADR-0053 Open
   obligations). A run on another platform under that pin is unpinned.
4. **What enforces a pin is measured.** The install scripts and the wrappers that refuse an unpinned binary are
   removed from `manifests/EXCLUDE`, so that a checkpoint fixes them along with the pins they enforce (finding F2).
   ⟨R1⟩ The same holds of what `manifests/EXCLUDE` keeps out under `.claude/` and `.github/`: the harness's permission
   list, the skills that direct ratification and manifest cutting, the record lint and manifest-cutting script that
   CI and the custodian run, and the workflows (F7). **A tool that measures the corpus, or that a gate runs, is
   measured with it** *(drafter's choice; the alternative, declaring each as a trusted-base row, is open)*.
5. **The build host is a Build principal's host.** It is ephemeral, built from a declared image, and appraised as
   ADR-0034 appraises a guest, at whatever rung the deployment declares. A host that outlives its round is declared as
   a degeneracy. ⟨R1⟩ **One such degeneracy stands today.** The proofs' evidence is produced on the custodian's own
   arm64-darwin machine, which is neither ephemeral nor appraised, under a prover pin whose release upstream no longer
   serves, and CI cannot rerun it (ADR-0069 §10.2, G-3). It is declared here (F8).
6. **The key ceremony comes before any key a deployment trusts exists** (ADR-0025 Open obligations). Dev keys never
   cross into a deployment (G6). Anchor, bundle, verifier, identity-provider and gate-runner keys are hardware-held,
   each with a custody row *(drafter's recommendation; an HSM is named in ADR-0045 only as delegated for
   availability)*.
7. **Order of stand-up** *(drafter's choice)*. Each step rests only on the ones before it:
   1. tools by digest;
   2. the toolchain's reproducibility check;
   3. the floor gates;
   4. the specifications and their results;
   5. the mechanism build.
8. **At genesis**, all of this is declared and not yet independently checked. It is T-0045-11's identity, and the
   full-corpus review of ADR-0029 A2 is where it is first read by another.

### 5. Phase 2: the development process is a Build round, and the tandem developer is two parties on opposite sides of a gate ⟨K1⟩ ⟨K4⟩

#### 5.1 The agent half is a havoc drafter, `Mediated`, and outside the trusted base

**The assistant is to the corpus what a Thinker is to the mechanism.** Nothing it produces takes effect except
through the custodian's act, as nothing a Thinker requests takes effect except through an admit. Under ADR-0045 §2 it
cannot be a row: its failure can add anything to a draft, and its identity is issued by nothing. So it is **excluded**,
as models are, and every claim rests on the act that stands between it and the corpus *(drafter's choice; the
alternative, a trust-root row for the assistant, fails §2's test)*. The assistant is held to Build's alphabet as
closely as its harness can express it:

| ADR-0022 verb | What the assistant may do | Control |
|---|---|---|
| `Read` | The repository and the sources the session names | **Everything read from outside the corpus root is `untrusted` ingress**: web pages, issue and PR text, tool output, files from elsewhere. An instruction found there is content, not a request (ADR-0048 §3's rule, applied to the drafter). ⟨R1⟩ **Run-derived material marks the session.** A session that has read an intake object, a trace or a Report marks what it drafts, and §8's removal test counts the draft as Run-originated |
| `Draft` | Write in a worktree or a session branch | No write to the default branch. No credential that could make one |
| `Invoke` | Allowlisted tools only | The harness's permission list is a tracked, gated artifact, and a change to it is reviewed as a change to a floor. ⟨R1⟩ It is not yet measured: `manifests/EXCLUDE` keeps `.claude/` out (F7). Network egress goes through a declared allowlist. Credentials are injected by the proxy and scoped to one repository and one branch. ⟨R1⟩ Whether a session's credential could also push a tag or another branch was not checked (A-0070-2). No secret is in the workspace |
| `Emit` | A session record | Every commit carries the session link (already the case). The session record names the model that served it, outside the corpus |
| `Submit` | Propose a branch or pull request | The custodian's merge is the `Vote`. **The assistant never votes**, never ratifies, and is never the reader that satisfies ADR-0029 A2 (the `ratifying-records` skill already says so) |

Further rules for the agent half:
- **A claim the assistant marks Met is a claim, not evidence.** Every Met carries the command and digest that make it
  checkable. The custodian, or CI (§5.3), re-runs it before ratification.
- **One session drafts. A different reader reviews.** A second session of the same model is independence of context
  and not of lineage (the review, §1). It does not count as A2's reader unless the custodian rules that it does.
- ⟨R1⟩ **The exclusion holds only as far as A-0070-1 does.** A Thinker is safe because its admit is mechanical and
  total over a typed alphabet. The custodian's merge has no predicate, and admits any file at any length. So the
  exclusion rests on a person reading, and CR-61 is the evidence that reading falls behind. Where A-0070-1 does not
  hold, the assistant and the custodian together are T-0045-11's identity. That, and not an exclusion, is then what
  the corpus can claim.
- ⟨R1⟩ **What a merge reads is bounded** *(drafter's recommendation)*. A session's pull request touches one record,
  or one artifact and its tests, so that the merge reads one thing. Every Met it states is re-run by CI and not by
  hand.
- ⟨R1⟩ **The assistant does not grade itself** *(drafter's choice)*. A change to a checker a gate runs, to `.claude/`,
  to `.github/` or to `manifests/EXCLUDE` is drafted alone. It is gated by the base's copy of each checker (§5.3), and
  read as a change to a floor.

#### 5.2 The human half is at the gate, and the gate is hardened

**The custodian is not evictable, so the custodian is at the gate** (ADR-0002 A2, B14). Nothing can make the gate
safe while custody is (1, 0). What this record asks for is that it be attributable and hard to steal *(drafter's
choices)*:
- **Account and keys.** A hardware-backed second factor on the repository host. Commits and tags signed with a
  hardware-held key. The allowed-signers file tracked, so that a signature can be checked from the tree. ⟨R1⟩ A
  signature is checked against the allowed-signers file of the tagged commit's parent, so that adding a signer is
  itself signed by one already allowed.
- **Branch protection on the default branch.** No direct push. No force-push. Merge only through a pull request whose
  required checks (§5.3) have passed. As ADR-0069 §9 C-2 has it, a carrier's checks may refuse and never admit. ⟨R1⟩
  GitHub reports `main` as protected. Which of these rules it holds was not read.
- ⟨R1⟩ **The custodian merges, not the host.** A merge made in GitHub's interface is signed with GitHub's key, and
  the 45 signed commits at `981bc77` are all such merges. A ratifying merge is made and signed locally and then
  pushed, or it is not a ratification.
- **Ratification is a tagged act.** A Batch is a signed tag over the merge commit. The tag, not the merge, is the
  ratification's instant. ⟨R1⟩ The tag's message carries the SHA-256 of the Batch's manifest (ADR-0033). A tag signs
  a commit id, which is SHA-1 and locates the tree rather than identifying it (ADR-0069 §9 C-5): the gap F1 finds in
  the bundle.
- **The custodian's own environment is declared.** It is part of T-0045-11's identity: which machine ran what, and
  that machine's toolchain, recorded in results files as they already are.
- **The residual.** At (1, 0), one compromised account is a compromised corpus. That is T-0045-11's failure as it
  already stands. The bootstrap's custody (ADR-0029, at least five humans) is what removes it, and nothing here does.
  ⟨R1⟩ A signature also does not stop the host from withholding the newest tag, or from serving an older one that is
  validly signed (§10).

ADR-0069 §10.2 repurposes f1-tla's workflows as this repository's carrier. §10.3 makes them evidence for the
custodian's ratification during genesis. ~~Which of the checks above those workflows run was not read for this draft.~~

- **Pace is bounded by review** *(drafter's recommendation)*. While a checkpoint is owed, or more than an agreed
  number of records stand Proposed and unread by anyone but their drafter, new drafting waits. This is the review's

### 6. Phase 3: promotion to production keeps ADR-0024's quorum, and binds it to computed provenance, loaded bytes and a staged reach ⟨K1⟩

1. **ADR-0024 stands**: a unanimous grant quorum, veto seats, author recusal, and a vote bound to (artifact digest,
   gate-evidence digest, rules epoch). Nothing here lowers it.
2. **Provenance is a projection, for every artifact.** ADR-0035 makes Persona lineage a projection of the Build log
   because "a gate over manifests checks what the author claims". The same holds of every artifact's provenance and
   bill of materials, which are projected from the sealed round (§3 (a), (c)) *(drafter's choice; this generalizes a
   Proposed record, and stands or falls with ADR-0035 §1's method)*. In SLSA's terms, the provenance is generated by
   the platform and not by the tenant.
3. **The signature binds the bytes that load** (§3 (b)). For a bundle, the signed digest is over the tarball's
   `policy.wasm`, `data.json` and `.manifest`, and the mechanism recomputes it at load. ADR-0069 §7 S-1 has the
   signing stage recompute the digest from the bytes. The recomputation at load is what this record adds, and it is
   where F1 is.
4. **Code is reproduced before it is voted on.** ~~Two builders, on toolchains from different sources, produce the same
   digest, or the promotion stalls. This answers T-0045-30's residual as far as the two toolchains are independent,
   which is the diverse-double-compiling argument, and no further.~~ ⟨R1⟩ Two builders that share no host, account or
   key build from the same pinned toolchain and produce the same digest, or the promotion stalls. Two different
   toolchains do not produce the same bytes, so the first draft's rule could not be met. Two copies of one toolchain
   fetched from two places are not independent either. **The toolchain is checked apart from any one release**
   *(drafter's choice)*: by diverse double-compiling of the compiler at each move of its pin, where a second compiler
   exists to do it (for Rust, mrustc's bootstrap, from the drafter's knowledge). No second Rego-to-Wasm compiler
   exists, so a bundle's Wasm is reproduced on the one compiler, and T-0070-5 stays a trust root. This answers
   T-0045-30's residual as far as the builders and the double-compiling are independent, and no further. **A grant
   seat reads the second builder's
   evidence**, which is evidence not derived from the author's artifacts (A4). ADR-0069 §6 G-4 finds that mechanism
   code has no gate of its own, and that it cannot promote until a record gives it one. This is that gate.
5. **Reach is staged** *(drafter's recommendation; the CrowdStrike scenario's `proposed:StagedPromotion`)*.
   - A promotion's reach is a field of the tally. It advances ring by ring, and no ring is reached until the previous
     ring's bake-in has passed without a finding.
   - ⟨R1⟩ **Silence is not a pass.** A round counts toward a bake-in only with evidence that the ring's Observers and
     correlator were live for it. A round without that evidence does not count, so a monitor outage stalls the advance
     instead of passing it.
   - **A finding may stop the advance, and never cause it** (ADR-0007).
   - The bake-in is counted in rounds of the ring, because an advance adds reach and ADR-0032 §2 gives a local clock
     only to intervals that subtract. ⟨R1⟩ Rounds a principal can start do not count, since TM1 could start them to
     shorten its own bake-in. Only rounds the operator's schedule opens count, at a rate the tally declares.
   - ⟨R1⟩ **An advance adds nothing the vote did not.** The quorum votes the whole staged reach. An advance carries out
     its next ring, so it needs no new quorum, and a finding stops it.
   - The scenario's reason: "A unanimous quorum of reviewers who all trust the same validator adds nothing here".
     Staging does not depend on the reviewers being right.
6. **Distribution fetches nothing at runtime except by digest.** The mechanism refuses an artifact whose digest is not
   in the promoted set under the current rules epoch (ADR-0027 §1, ADR-0030 §3). Freshness is the rules epoch, which
   is a log position and not a clock.
7. **Retreat is a revocation, and return is a promotion.** Revoking a promoted digest subtracts. It is local and an
   operator's (ADR-0031 §5). Going back to an earlier artifact is a promotion like any other, because it adds the
   earlier artifact's reach back.
