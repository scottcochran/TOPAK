## Context

ADR-0046 declared the formal layer's method: TLC checks mutations and witnesses at small constants, and TLAPS proves
the invariants. Its A1 gave the prover a certified configuration, in which an SMT answer counts only with a proof
an independent checker accepts. Three residuals remain, and `spec/proof-certification.md` lists them:

- **LS4**, for the temporal step of every theorem: "the invariant holds initially, every step keeps it, so it holds

cedar reaches by folding the authorizer term without a solver query, so they rest on the engine's row, T-0045-3,

## Decision

### 1. The method is declared

The formal layer gains a second deductive method, Lean 4, in three uses. Each is named by what its Lean states:

- **A re-encoding** of a TLA+ module: its constants, variables, `Init`, `Next` and properties written as a Lean
  transition system, each definition beside the TLA+ it transcribes. Its theorems are those of the module's
  `*_proof.tla`, proved by induction on the reachable states (`spec/lean/TopakSpec/Prelude.lean`, `invariant`). The
  induction is the step TLAPS hands to LS4.
- **A transcription** of a function of the reference: its types and body written in Lean, each beside the Rust. Its
  theorems are properties of the function, stated as a TLA+ module or a record states them. **A transcription may be
  proved to refine a re-encoding** ⟨R2⟩: the code's step is shown to be a step of the module, so every invariant
  proved of the module holds of every behaviour in which the code takes that step. The first is the admit decision:
  `admit.rs`'s `compose` with the `topak-floor` wrapper, a `Decide` step of `FloorComposition`
  (`mechanism/lean/Topak/FloorRefinement.lean`). Its engine is a premise, Cedar's authorization rule over the
  module's floor, which is T-0045-3's own premise at the module's size; the lift is the module's own.
- **A statement in Cedar's model**: a policy set and schema of the floor, in cedar-spec's abstract syntax, generated
  from the floor's own files through the cedar CLI's parser (`floor/lean/gen.py`), for the genesis floor and, since R3,
  for the floor in force, the `emergency` stage the reference links ⟨R3⟩. Its theorems are gate claims under
  the model's semantics, and the model's proved theorems apply to them.

**The words** *(drafter's choice)*. ADR-0046 §1 reserves **proved** for a claim TLAPS discharged. A claim the Lean
kernel discharged is **proved in Lean**, of the encoding, the transcription or the statement it names; the corpus
writes it so, and never "proved" alone. **The TLA+ module, its TLAPS proof and the Rust stay canonical.** A Lean
result does not replace any of them; it is a second derivation with different premises (§2).

### 2. What a Lean result claims, and does not

A theorem proved in Lean holds of what the Lean states, under the kernel and the toolchain (§3). It is bounded by
neither constants nor a solver: `UnreadBounded` is proved in Lean for every K, R and MaxRound, `ContainedMeansConfined`
for every natural `Declared`, not only 0..3.

**It is not a claim about the frozen TLA+ text, the Rust, or the Cedar text.** Each use adds one premise, which is
read and not checked:

| Use | Added premise | How it is kept |
|---|---|---|
| Re-encoding | The Lean transition system is the TLA+ module | Each definition carries the TLA+ it transcribes; `Prelude.lean` states the encoding's conventions, and each file the places a reading was chosen |
| Transcription | The Lean function is the Rust function | Each definition carries the Rust it transcribes; no Rust-to-Lean translator was run |
| Statement in the model | The cedar CLI's parse of the Cedar text, and `gen.py`'s walk of it, are the policies and schema | The generated files carry the sources' digests and are regenerated by every results run |

The model's fidelity to the Rust engine is **T-0045-3's own premise** ("the Cedar engine, as faithful to the Lean
model"), not a new one. The floor's totality claim therefore moves from cedar's term folding to the model's proved
validator soundness plus T-0045-3: the engine is trusted for what T-0045-3 already says, and cedar's folding code is
no longer in the claim.

**Closed evaluations in the floor package use `native_decide`**, which trusts Lean's compiler for the evaluation
and shows as one axiom per use in `#print axioms`. The kernel's `decide` was tried and cannot reduce the model's
definitions, which are built by well-founded recursion. The spec and mechanism packages use none: `propext` and
`Quot.sound` at most, and `Classical.choice` in `NonComposition` alone, whose `Erase` step cases on a set
membership as TLA+ does.

**`#print axioms` is not enough by itself**, and every results file carries a **replay**: `leanchecker --fresh`
replays every constant the package's root reaches, Lean's library and cedar-spec included, through the kernel in a
fresh environment from the stored build. The control run on 2026.10.05 (`spec/proof-method.md` §5b): a scratch
module that adds `False` with the kernel check switched off (`debug.skipKernelTC`) builds, and `#print axioms`
reports a theorem resting on it as depending on **no axioms at all**; the replay refuses it, exit 1, in both of its
modes. The replay is the same kernel in a separate process, not an independent checker.

A Lean result does not replace a mutation row or a witness. Those are existential and stay with TLC, as ADR-0046 §2
says of the TLAPS proofs; each Lean file carries, as each proof module does, one lemma per mutation naming what it
admits. Nine mutated encodings for the small modules, nine for the parameterized ones, three for the code and two for
the floor were built on 2026.10.05, and each failed in the theorem its mutation breaks (each package's README).

the subtract-only test: an unsound kernel accepts a false theorem, and a mechanism built to it admits what the
theorem forbids. Their identity is fixed by digests every results file prints and `tools/LEAN-PIN` pins. On
ratification ADR-0045's Annex A gains, in its third group (the verified object's evidence, beside T-0045-31), the next
free id; T-0045-32 to 36 are the rows its A1 and A2 added in Batch 34:

### 5. The premise table gains the Lean route, and no premise changes

`spec/theorem-premise-binding.md` is revised with this record *(drafter's choice: in place, as its header provides
for)*:

- The *Checked in* column names the Lean file beside the proof module for every property §4 covers, for example
  "`Seats.tla`; proved in `Seats_proof.tla`; proved in Lean in `spec/lean/TopakSpec/Seats.lean`". The
  `FloorComposition` rows name its re-encoding, and also "the code's decision refines its `Decide`, in Lean:
  `mechanism/lean/Topak/FloorRefinement.lean`" ⟨R2⟩.
  The floor gates' row names `floor/lean/` for totality, non-vacuity and discrimination.
- **The row premises are unchanged** *(drafter's choice)*. With two proofs a property holds if T-0045-31 holds, or if
  T-0045-37 holds and the encoding is the module. That is a disjunction, and the table's form, holds = ¬(B·¬d), is a
  conjunction of premises. The table keeps T-0045-31 as the premise and records the Lean route as evidence; a
  deployment that excludes T-0045-31 is told by the *Checked in* column that a second route exists, not by the
  inventory. The finding below keeps the question. **The choice is harmless only while a Lean result corroborates
  a TLAPS proof** ⟨R1⟩: dropping the second route then loses nothing the table claims. It stops being harmless when
  a Lean result carries a claim about the code, which the next bullet governs.
- **The floor gates' row** gains, in its reference column: totality's 23 `holds°` rows are proved in Lean of the
  floor under cedar-spec's model, resting on T-0045-37 and T-0045-3 and no longer on cedar's term folding.
- **The BASE paragraph** gains one sentence: a property whose *Checked in* column names a Lean file is also proved in
  Lean, of that file's encoding, on T-0045-37.
- **A stage of the refinement chain discharged through Lean waits on the table** ⟨R1⟩ *(drafter's choice)*. ADR-0045
  Annex B and ADR-0033 name stages 2 and 3 of T-0045-28's chain as a Lean model of the mechanism, differentially
  tested, and its compilation. A model proved in Lean to refine the specification would refine the re-encodings
  under `spec/lean/`, which is where the specification is in Lean, and not the frozen TLA+ text. Its conclusion, that
  the running code keeps an invariant, would rest on T-0045-37 and on each refined encoding being its module, and
  would reach the TLAPS theorems, and T-0045-31, only through that encoding premise. Through such a stage a row
  would rest on T-0045-37 and the encoding in place of T-0045-28 and T-0045-31, while a deployment that does not
  take the stage keeps the second set: two alternative premise sets for one row, which the table's conjunctive form
  cannot state and would misstate. **No ADR-0033 addendum cites a stage as discharged through Lean until** (a) the
  table can state alternative premise sets for a row, or the corpus has chosen, row by row, which set its inventory
  computes; and (b) the encoding of every module the stage refines is a premise the table names, with a check
  behind it or a reading by someone other than the drafter. A fidelity that is read by the drafter alone suffices
  for corroboration; it does not suffice for a premise that a guarantee about the code carries.
  **`FloorRefinement` is not such a stage** ⟨R2⟩. It refines one action of one module, with the engine premised and
  the lift the module's own, against a floor of four policies that is neither the genesis floor nor the floor in
  force. It is evidence toward T-0045-28 in the sense of §6, and no addendum may cite it as a stage.

## Options considered

- **Keep the Lean results as derived evidence, without a record.** Rejected: under ADR-0045 §5 a prover is a row,
  and a row enters by record. Results nobody may cite are not evidence the corpus can use.
- **Replace TLAPS with Lean.** Rejected: the TLAPS proofs are frozen by ADR-0046, prove the frozen text directly,
  and have their own certification. A second route with a different residual is worth more than a swap.
- **Embed TLA+'s semantics in Lean**, so that a Lean theorem is of the TLA+ text and the encoding premise goes.
  Not taken *(drafter's choice)*: a project of its own, and the re-encodings are short enough to read beside the
  text, which each file arranges.
- **Translate the Rust mechanically** (Aeneas or hax) instead of transcribing it. Not taken now: neither was tried
  on this crate. For twenty lines of pattern matching and one inequality, a transcription read beside the source is
  cheaper than a translator's trusted base. An open obligation keeps it.
- **One row per package.** Rejected: one kernel. cedar-spec's model is already T-0045-3's premise, and its proofs are
  kernel-checked like the rest.
- **A delegated row.** Rejected, for T-0045-31's reason: an unsound kernel adds.

## Consequences

- Twelve proof modules' theorems, including the three modules the certified run does not certify, have a second
  derivation in which the temporal step is a kernel-checked induction and no SMT solver is used.
- The floor's totality claim rests on the model's proved validator soundness and the engine's fidelity to the

## Findings

1. **`#print axioms` misses a declaration added past the kernel.** The control in §2: a theorem resting on `False`,
   added with the kernel check off, reports no axioms. The replay refuses it. A results file without the replay
   would have certified it.
2. **The premise table cannot say "either proof".** Its form is a conjunction of premises; two independent proofs
   give a disjunction. §5 keeps the table conjunctive and records the second route as evidence. **That is harmless
   while Lean corroborates and load-bearing once it carries a claim about the code** ⟨R1⟩: a refinement for
   T-0045-28 done in Lean would refine the re-encodings, rest on T-0045-37 and the encodings, and reach T-0045-31's
   theorems only through them. §5's last bullet makes settling this a precondition of any such stage.
3. **`Confinement` needs no bound on `Declared`.** The TLAPS proofs assume `Declared ∈ 0..3`; the Lean proofs hold
   for every natural, with no assumption. The theorem is stronger than its statement, as ADR-0046 found for
   `Coupling`'s `K < R`.
4. **The model's entity validator expects the schema's action entities in the store**, which the Rust engine adds
   implicitly. `gen.py` writes them in. The API surfaces differ there; the semantics do not.
5. **A toolchain tag floats**, as TLAPS's pre-release did: elan's `stable` resolved to a version not installed. Every
   package names its toolchain in `lean-toolchain`, and the pin fixes the binaries by digest.
6. **Three floors, and the one that runs is stated in Lean nowhere** ⟨R2⟩. `FloorRefinement` refines
   `FloorComposition`'s floor of four policies; `floor/lean/` states the genesis floor, 17; the reference links the
   `emergency` stage of the proposed floor, 28 (`topak-floor/src/lib.rs`). Each result is true of the floor it
   names, and none is of the floor in force. ⟨R3⟩ Since R3 `floor/lean/` states the floor in force too, so the
   gate claims are of the floor that runs; `FloorRefinement`'s floor is still the module's four policies.
