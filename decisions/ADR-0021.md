# ~~ADR-0016~~ ADR-0021 — Build emits to the effect stream; Build has an Observer ⟨N1⟩

**Status:** Proposed · 2026.09.12
**Relates to:** ADR-0002, ADR-0003, ADR-0005, ADR-0006, ADR-0007, ADR-0008, ADR-0015, ADR-0024 ⟨R1⟩.
**Closes:** the open item "Build's membrane has no effect stream," raised in the 2026.09.12 Theory of Operation checkpoint §1.
**Blocked on:** ~~ADR-0022 (Build's action alphabet). Decidable in principle, undraftable in detail until that exists.~~
The ADR-0003 no-tiered-storage clause (§7's retention divergence). ADR-0022 §1–§5 are Accepted (genesis) and
supply the alphabet ⟨R2⟩.

---

## Context

ADR-0002 accepted `Build(Contain) → Run(Contain)`: `Contain` is one component instantiated
twice, parametric in its occupant. Agents drafting specifications and Rego inside Build are
principals under mechanism enforcement, exactly as agents are in Run.

The instantiation is incomplete. In Run, `Contain` has an emission substrate — ADR-0003's topic
per principal per epoch/round, sealed on emit completion — which carries three loads at once:

- **Detection.** It is what the Observer reads. ADR-0007 holds that semantic judgment is never a
  lift, which makes every semantic concern an Observer finding rather than an enforcement
  decision. ADR-0008 gives the Observer a replicated, fault-domain-independent home.
- **Erasure.** The topic is the unit of erasure under ADR-0006 ⟨R1⟩.
- **Attribution.** The topic carries the epoch and lease under which each action was taken.

In Build, `Contain` currently carries none of them. Build's unit is an artifact, not a round,
and an artifact is the output of many principal actions rather than a record of them.

**The consequence is sharper than an asymmetry.** ADR-0007 and ADR-0008 have no attachment point
in Build, which means Build has enforcement and no detection. TOPAK's published inversion is
that the Byzantine threat *lives in Build* — the vacuously true predicate sailing through green
gates, Moon & Varshney §4.6 and Appendix B. A domain declared hostile, containing agents that
author the policy floor and the specifications, with a syntactic envelope and no Observer, is
the most direct contradiction currently on the board. "Effect stream symmetry" undersells the
decision; the decision is whether Build has an Observer at all.

Three candidate answers were available.

**Option A — reuse the round-topic scheme.** Build's `Contain` emits to topics under ADR-0003's
existing granularity, with a Build-appropriate definition of "round."

**Option B — a distinct substrate.** Build is already an artifactory for Orch: a durable,
content-addressed store. An attestation chain over it (in-toto / SLSA shape) is native to what
Build already is, and long retention is a solved problem there.

**Option C — no emission; Build's `Contain` is enforcement-only.** Honest, cheap, and states
outright that detection is a Run-domain capability.

Two pieces of analysis decided it.

**Frequency runs the right way, not the wrong way.** The checkpoint flagged broker metadata
pressure as the cost of Option A. On inspection the concern is inverted. Run rounds are
sub-second to seconds; Build rounds are pipeline invocations lasting minutes to hours. If the
topic-per-principal-per-round scheme is affordable at Run cadence, it is affordable at Build
cadence *a fortiori*. Build's pressure is not topic creation rate.

**Retention runs the wrong way, and that is the real cost.** Build's audit horizon is the
production lifetime of the promoted artifact, which is far longer than Run's durability window.
ADR-0003's no-tiered-storage clause was written against Run's horizon and does not obviously
survive Build's. This is the genuine divergence, and it is a retention parameter rather than a
mechanism difference.

**Timing is trivial in Build.** Run's `W < L < D` chain is hard: the propagation window is ~1s
and no human fits inside it, which is why Run is HOTL. Build is PC/EC and the promotion gate
blocks, so the only constraint on Build detection latency is that it complete before the gate
clears — satisfiable by construction. Detection is *cheaper* in Build than in Run, which makes
its absence there harder to defend, not easier.

---

## Decision

**Option A, with retention as a documented divergence.**

1. **Build's `Contain` emits to the effect stream** under ADR-0003's scheme, unchanged in
   granularity, access-control model, replay authorization, and sealing discipline.

2. **A Build round is one pipeline invocation.** Each principal seat within it holds its own
   topic for the duration, exactly as in Run.

3. **Sealing moves from emit completion to gate submission.** Run seals a topic when the
   principal finishes emitting. Build seals the principal's topic set when the artifact is
   submitted to the promotion gate.

4. **Every promotion vote covers artifact digest ∧ sealed topic-set digest.** ⟨R1⟩ Voters sign
   provenance, not only the product. Promotion is a quorum of grant seats under ADR-0024, not a
   single approver's signature; the sealed topic-set digest is the gate-evidence digest that
   ADR-0024 §3 binds each vote to (S6-8).

5. **Build has an Observer,** with the same placement discipline as ~~ADR-0008~~ ADR-0038 ⟨R3⟩ — ~~replicated~~
   *one `observer` seat per cell, more combining by any-of* ⟨R3⟩,
   fault-domain-independent, not colocated with the Thinker it watches — and with the
   monoculture declaration applying: a cross-family Observer, since Build agents and their
   Observer sharing a model family is a shared blind spot at the point where the floor is
   authored.

6. **The Build Observer is deny-only.** Per ADR-0007's monotonicity, a finding is admissible as
   a promotion block or a quarantine trigger and is never an admit precondition. Observer
   silence does not authorize promotion; the grant seats do ⟨R1⟩, which under ADR-0024 §5 is
   where the Observer instead holds a veto seat.

7. **Retention diverges by parameter.** Build round topics are retained for the production
   lifetime of any artifact promoted from that round. The mechanism is identical; the
   retention value is not. ADR-0006 erasure applies unchanged — the topic remains the unit of
   erasure ⟨R1⟩, which is what makes long retention tolerable under an erasure demand.
   (ADR-0003 rejects crypto-shredding as the primary mechanism; ADR-0006's mechanism is deletion
   of the sealed topic plus deletion from the governed plaintext store — S6-11.)

---

## Consequences

**Positive**

- One mechanism, one erasure unit, one Observer interface, one replay-authorization model
  across both domains. ADR-0003, ADR-0006 and ADR-0008 extend rather than fork.
- Build gains a detection layer in the domain TOPAK declares hostile. ADR-0007's semantic-lift
  prohibition stops being vacuous in Build.
- **Partial progress on the gate-approver hole** ⟨R1⟩**.** Under ADR-0024 the voters are
  `Mediated` principals rather than an approver at the gate, since the anchor evicts them; the
  gate has moved up to the anchor's key-holders (ADR-0002 A1, at archetype custody). Voters are
  still outside `Contain` and outside every containment theorem. Signing over a sealed topic set
  makes the *basis* of their votes an audited object. It does not make them `Contained` and should
  not be written as if it does.
- Gives ADR-0014 a provenance object to reason about: "who may propose a floor change" now has a
  record of how the proposed floor was authored.
- ADR-0015's boundary effects audit acquires a Build-side surface to audit.

**Negative**

- Observer instance count rises. ADR-0008's ~9 versus ~40 argument was made for Run; the Build
  figure is unestimated and this ADR does not supply it.
- Long-horizon retention on Build topics conflicts with ADR-0003's no-tiered-storage clause.
  This is the second clause of 0003 to look independently supersedable — the first was wrapper-
  Rego masking — which strengthens the case for the outstanding 0003 bundling check.
- Adds a required component to Build at the same time as the floor-fitness gate is outstanding.
  Build's gate inventory is growing faster than it is being ratified.

**Neutral / requires follow-up**

- ~~**The action alphabet is the blocker.** Build principals write files, invoke tools, and open
  promotion requests; none of it is typed. ADR-0007 guarantees a finite, totally-extracted
  alphabet in Run, which is what makes both `bundle ⊑ floor` and Observer typing decidable.
  Build has no such guarantee yet. This ADR is unimplementable until it does, and should not be
  ratified as though the alphabet were a detail.~~ **Discharged by ADR-0022 §1–§5** ⟨R2⟩, ratified
  2026.09.23: six typed variants, finite in variants. The alphabet is *total* only under ADR-0022
  §6's confinement obligation, which is unratified, so the Build Observer reads a typed stream that
  a principal with a shell can go around. That is the sandbox gap, and it does not block this record.
- Whether the Build Observer reads the same alphabet as the Run Observer, or a Build-specific
  one, is open and follows from the above.
- Whether Build's emissions fall under ADR-0004's control-plane / cognitive-payload separation
  in the same partition is untested here.
