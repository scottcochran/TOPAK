## Context

Until 2026.09.24 the corpus argued about a mechanism that did not exist. The TLA+ artifacts checked envelopes, the
draft floor was gated with SymCC, and the Rego placeholder passed its tests, but **no running code composed them.**
Three questions the records could not answer from text alone:

1. **Do the records compose?** Each was written and checked against its neighbours on paper. Whether ADR-0022's
   alphabet, ADR-0030's composition, ADR-0031's lease, ADR-0024's tally and ADR-0015's ordering fit into one admit
   path was asserted, not shown.
2. **What do the unstated parts cost?** Every record defers something to "the mechanism". A build has to decide
   each of them, and until one exists nobody can list them.
3. **What is the reference for?** A reference implementation can drift into being mistaken for the verified object.
   The ToO is explicit that the archetype is unshipped (ToO §8.1) and that `Contained` may have no members (ToO
   §2.4). A running program invites the opposite reading.

The build answered the first two, subject to the scope in §6: the records compose, and it took **22 assumptions** and
**17 gaps** to make them run. It also produced **ten findings** about the corpus itself, three of them caught only
because code ran (§7). The third question is what this record decides.

## Decision

### 1. The reference is evidence, of the same kind as a TLA+ check

`mechanism/` is a **reference implementation of the admit path**: epoch fence → lease → syntactic lift → policy
floor → bundle → consensus-ordered admit → effect, for Build's six actions and two provisional Run actions.

- **It is evidence, not attestation**, exactly as G2 §3 classifies the TLA+ artifacts: a discrimination test run by
  the author at small scale. It shows the records compose and that stated mutations fail. It proves nothing.
- **It is not the verified object.** ADR-0010's verified object is a mechanism release, promoted under ADR-0024.
  The reference has never been promoted, and no promotion pipeline exists to promote it. Nothing in it is in any
  TCB.
- **It is not a deployment.** It declares no degeneracies because it claims no conformance. Every lease it issues is
  rung 0, so every principal it serves is `Mediated` (ADR-0031 §3), and the TLA+ containment theorems do not describe
  it.
- **It may be cited** the way a TLA+ artifact is: by digest, with the claim scoped to what the cited tests check.
  ~~Until the tree is committed, citation is by file path and date only, and carries no digest.~~ A tree is cited by
  the digest of a SHA-256 manifest of its files, as a checkpoint is (G-C1), and the citation names the commit the
  manifest was taken from ⟨R1⟩.

### 2. The stack instantiates the letters by role

The letters name roles (ADR-0030 §2 for O). The reference fills each role with one instrument and records why.

| **O**, floor | Verified evaluator, linked, resident, minimal | `cedar-policy` 4.13 (the Rust engine), linked into the replica; `floor/genesis-floor.cedar` and `floor/genesis.cedarschema` compiled in **by path** and refused at startup unless their bytes match the gated digests | ADR-0030 §3: the Rust engine is the shorter assurance chain. **Substitution is by role.** Any row may change without amending this record, provided the replacement meets the
role's obligation and the change is recorded in the reference's assumptions register. The floor row cannot change
language without ADR-0030.

### 3. The replica fault model is crash-recovery

**The mechanism's consensus replicas are crash-recovery, not Byzantine.** A replica may stop, lose volatile state
and restart from durable acceptor state. It does not lie.

- **The premise is unchanged.** ADR-0007 makes *agents* Byzantine at every position. Agents never speak Paxos; their
  only path into the log is an admit the mechanism decides. The replicas are the mechanism, and the mechanism is
  inside the verified object's boundary.
- **Durability is part of the model.** A replica's promise and accepted vote must be durable before any reply that
  depends on them leaves the process. The reference fsyncs a write-ahead log per output batch, before sends.
- **Clocks buy liveness only** (ADR-0032 §1). Leader election reads a local monotonic clock; nothing in the safety
  argument does.
- **A Byzantine replica is outside the model.** That is a real residual: a compromised replica can propose any entry,
  including admits that no floor evaluated. The deterministic apply-time checks in §4 stop *stale* admits; they do not
  re-run the floor, so they do not stop *forged* ones. Replica authentication (mutual TLS) and a BFT consensus are
  both out of scope and both open (§8).

### 4. Admits are decided, then ordered, then re-checked

The admit decision and its commit are separated by time. An admit decided under epoch *e* can commit after a
revocation has moved the epoch to *e*+1.

- **The mechanism checks run twice**: once before the floor is consulted, and again, deterministically, when the
  committed entry is applied. The second run uses the state at the entry's log position. An admit that fails it is
  **void**: ordered, recorded, and without effect.
- **The floor and bundle are not re-run at apply.** Their decision is recorded with the digest of the frozen input it
  covers (ADR-0030 §4). What can go stale between decision and commit is the mechanism state (epoch, lease, rules
  epoch, round bound), and that is what is re-checked.
- **The effect runs only after commit**, only on the deciding replica. A crash between commit and effect leaves an
  admit with no effect, which is safe: absence of effect is not an event (ADR-0015).

**Ordering is not authorization.** A state change that subtracts authority needs no quorum (ADR-0031 §5, ADR-0024 §9),
but if it changes replicated state it must still be **consensus-ordered**, or replicas disagree about what is live.
Revocation (~~epoch increment~~ a targeted revocation or an epoch fence, ADR-0031 R3 ⟨R6⟩), abstention, expiry and end
of round are therefore log entries that any replica may propose and none needs to approve. ADR-0015's "denials are not ordered" still holds: a denial changes no state.

This section states for the mechanism what the reference had to decide to run. It is a candidate clarification of
ADR-0015 and ADR-0031, not an amendment. If ratified, those records gain a pointer, not a changed decision.

### 5. The bundle tier's fallback is an engine fallback, bound to the lease

**Stated in ADR-0030 §1** ⟨R13⟩, which carries the rule and its table since ADR-0030 R4 folded it in; accepted in
Batch 6. The reference implements it in `topak-bundle` (register I2 and I3), records the deciding engine in every
admit, and checks every row of the table in `fallback.rs` (six cases). Bundle signing (ADR-0030 §2) is **not
implemented** (§8). The text this section carried before R13 is quoted in History.

### 6. What the reference does not show

- **Confinement.** Nothing prevents an agent process with a shell, a network stack or a filesystem from bypassing the
  MCP front door entirely. The front door makes the alphabet the whole *protocol*; it does not make it the whole
  *channel*. This is ADR-0022 §6 unchanged, and the reference is its plainest illustration.
- **Tool hermeticity** (A2). Downstream tools are pinned by binary digest and schema digest and run with a cleared
  environment in the workspace. Their behaviour is not checked.
- **Anything about the Observer, the archive, erasure, masking, Persona attestation, or bootstrap.** None is built.
- **Scale, latency, or long-running behaviour.** No compaction, no snapshots; every admit waits for a consensus round.
- **That the floor is the right floor.** Floor fitness (MEASURE 2.13) is unowned.

## Consequences

**Positive**
- **The records are shown to compose**, subject to §6. Every link in ADR-0015's audit chain has running code: effect →
  admit → floor ∧ bundle → rules epoch → issuance.
- **The unstated parts are enumerated.** Twenty-two assumptions and seventeen gaps, each tagged in the code, turn
  "the mechanism will handle it" into a list.
- **The enforced floor is the gated floor**, by construction and by check.
- **Findings reach the records that own them** (§7), three of which no amount of reading would have produced.
- **The sandbox gap becomes demonstrable.** A reader can watch the mechanism refuse `../escape` through MCP and know
  that the same agent with a shell would not have asked.

**Negative**
- **A running program will be mistaken for the mechanism.** §1 says it is not. Saying so will not be enough, so the
  README repeats it and every lease reports `Mediated`.
- **The reference implements three Proposed records.** If ADR-0030 or ADR-0031 changes before ratification, the
  reference follows it, and code written against an unratified record is rework waiting to happen.
- **One author wrote the records, the checks and the code.** Agreement among the three is not independence.
  Correlated review failure (ToO §12 item 2) applies to code as much as to gates.
- **The reference will drift from the corpus** unless the pins and tags are kept. The floor pin fails loudly; the
  `PROVISIONAL` tags do not.
