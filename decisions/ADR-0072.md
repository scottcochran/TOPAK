# ADR-0072 — The reference reader is React with Material UI over the public API alone: every page arrives as complete HTML, reflows from 320 pixels, has a light and a dark scheme and a reading mode, and its WCAG 2.2 AA conformance is a dated audit a person signs

**Status:** Proposed · 2026.11.16
**Status note:** On the drafter's reading no confirmation criterion attaches. **C1:** no privileged path is touched.
**C2:** §7 claims conformance of a set of pages a release names, by audit, and makes no exhaustiveness claim about
the system. **C3:** nothing accepted is reversed. **C4:** no accepted record owes a reader. **Nothing here is
modelled, checked or built.** No reader exists. The corpus is read today as Markdown that a carrier renders.
**Pending:** none.
**Deployment position:** Archetype for §1 and §3 to §7, as requirements on any reader that claims them. §2 is the
reference's choice of libraries, and a deployment that makes another makes no declaration by doing so (§8).

**Closes:** nothing.

## Context

**ADR-0071 serves the documentation to any client, and no client exists.** The custodian asked for one built with
React and Material UI, with the alternatives listed ⟨K8⟩, and set five properties for it: responsive display, light
and dark modes, a minimalist reading mode, assistive access, and WCAG compliance ⟨K9⟩.

**The five properties are not equally checkable.** Reflow at a width, a contrast ratio and a missing text
alternative can be computed. Whether a screen-reader user can find the clause a runbook step rests on cannot. A
program that reports no failures has shown that it found none of the failures it can find. The corpus already has
words for this distinction: a gate that is mechanical (ADR-0007), a carrier's check that "may refuse and never
admit" (ADR-0069 §9 C-2), and an entry field that is "checked or claimed" (ADR-0049). §7 uses them for conformance.

**Part of accessibility is not the reader's to supply.** A text alternative, a heading's level, a table's header
cells and the language of a passage belong to the content. A reader can only present what it is given. ADR-0071
§8 makes those fields mandatory in what the API returns, so that this reader and any other start from the same
material ⟨K7⟩.

## Decision

### 1. The reader is a client of the public API and nothing more ⟨K7⟩

- **R-1. The reader calls only the API of ADR-0071 §7**, with no credential a third party's reader could not hold.
  It has no route to the store and no endpoint of its own. This is ADR-0071 §8 U-1 seen from the client.
- **R-2. The reader holds no content.** A page is a rendering of a unit's revision in a view (ADR-0071 §2, §4), and
  its address names both. A link to a page in view `G11` returns that page for as long as the service runs.
- **R-3. The reader states nothing of its own.** Every sentence about TOPAK on a page comes from a unit. The
  reader's own text is navigation, labels and its accessibility statement (§7).
- **R-4. Every view is rendered by the same code path.** ADR-0071 §4 makes a checkpoint or a release equal to
  `latest` at the API. The reader keeps that at the screen: search, level switching, bindings and reading mode work
  in every view, and the only difference a past view shows is a line saying which view it is.

### 2. React and Material UI ⟨K8⟩

**The reference reader is written in React, with Material UI as its component library.** Both are MIT-licensed.
Their versions are pinned by the lockfile, and the lockfile is cited by digest when the reader is built, as
ADR-0069 §10.2 pins every tool.

- **M-1. A component is used as the library ships it only where it passes §6.** Where one does not, the reader
  wraps or replaces it, and the audit report (§7) names it *(drafter's choice: Material UI follows the WAI-ARIA
  authoring practices for most components, and that is the library's claim, not a result this corpus holds)*.
- **M-2. The two colour schemes of §4 are one theme with two schemes**, expressed as CSS variables, so that the
  scheme is set in the HTML the server sends and does not wait for a script.
- **M-3. Material Design's look is not a requirement.** The theme sets type, measure, spacing and colour for long
  technical reading. Density, elevation and motion defaults are turned down to what §5 and §6 allow.

### 3. Responsive display ⟨K9⟩

- **RD-1. One document, one layout that reflows.** There is no separate mobile site. Content reflows without loss
  and without scrolling in two dimensions at a width of 320 CSS pixels (WCAG 1.4.10), and remains usable at 400%
  zoom.
- **RD-2. What cannot reflow scrolls inside its own region.** A wide table, a code block and a diagram keep their
  shape. Each sits in a labelled, keyboard-focusable region that scrolls by itself, and the page around it does not.
- **RD-3. Orientation is not locked** (1.3.4), and a pointer target is at least 24 by 24 CSS pixels (2.5.8).
- **RD-4. Navigation collapses, and content does not.** At narrow widths the navigation becomes a disclosure the
  reader opens. The unit's text, its level switch (ADR-0070 §4), its status marks and its bindings stay on the page.

### 4. Light and dark ⟨K9⟩

- **LD-1. Two schemes, and the first visit follows the device** (`prefers-color-scheme`). A reader's own choice
  overrides it and is kept on that device. The choice is never part of a page's address.
- **LD-2. Both schemes meet the same contrast**: 4.5 to 1 for text (1.4.3) and 3 to 1 for the parts of controls and
  graphics a reader needs (1.4.11). A scheme is audited separately (§7), since passing in one says nothing of the
  other.
- **LD-3. Nothing is said by colour alone** (1.4.1). A status mark (ADR-0070 §5) is a word, and a stale binding
  (ADR-0070 §7) is a word and an icon with a text alternative.
- **LD-4. A diagram has a rendering for each scheme, or draws in the text colour.** A diagram with a fixed light
  background on a dark page is a defect. The corpus's diagrams are generated (`diagrams/`), so the generators owe a
  second palette (Open obligations).
- **LD-5. A user's forced colours are respected.** Where the device imposes its own palette (`forced-colors`), the
  reader does not override it.

### 5. Reading mode ⟨K9⟩

**Reading mode shows one unit, at one level, as a single column of text, with nothing else on the page.**

- **RM-1. It is the page as the server sends it** *(drafter's choice)*. Every page arrives as complete HTML with its
  styles. Reading mode is that document without the navigation, and it needs no script to read, to follow a link or
  to print. Scripts add search, the level switch without a page load, and the colour-scheme control.
- **RM-2. It has its own address**, so that a reader can be sent to it and a device's own reader view can parse it.
- **RM-3. The column is at most 80 characters wide**, with the size, line spacing and paragraph spacing of text
  under the reader's control and no loss of content when they change (1.4.12; 1.4.8 at AAA).
- **RM-4. Reading mode may hide navigation and never a mark or a binding.** The view, the unit's status marks and
  its staleness stay at the head of the column, and each binding becomes a numbered note at the foot with its record
  clause, module or policy and its digest. ADR-0029 §3 requires that a publication citing an unconfirmed record's
  guarantees say "author-ratified". A mode that dropped the words to look cleaner would make every page in it a
  publication that does not.
- **RM-5. Print is reading mode on paper**, with each link's target and each binding's digest written out.

### 6. Assistive access ⟨K9⟩

- **AA-1. Native elements first.** Headings, lists, tables, buttons, links and disclosures are the HTML elements,
  and ARIA is added only where HTML has no element for the pattern. Every control has a name, a role and a value a
  program can read (4.1.2).
- **AA-2. The page's structure is the unit's structure.** Heading levels, table headers, list nesting and reading
  order come from the content tree ADR-0071 §8 returns (1.3.1, 1.3.2). The reader does not flatten them for layout.
- **AA-3. Everything works from a keyboard** (2.1.1), with no trap (2.1.2), in an order that follows the reading
  order (2.4.3), with a focus indicator that is visible (2.4.7) and not covered by a fixed header (2.4.11). A skip
  link leads to the unit's text (2.4.1).
- **AA-4. The level switch is a set of three named controls, MI, SI and DI**, each a link to an address, so that it
  works without a script and announces which level is shown. Nothing a reader needs appears only on hover (1.4.13).
- **AA-5. A change the reader did not ask for is announced.** A route change moves focus to the new unit's heading.
  Search results and a notice that a view is not the latest are status messages (4.1.3).
- **AA-6. Motion is off where the device asks** (`prefers-reduced-motion`), nothing flashes, and nothing times out.
- **AA-7. Non-text content carries the text the unit supplies** (1.1.1). A diagram has a short alternative and a
  long description, and the long description is on the page, not behind the image. Where a unit supplies none, the
  reader shows the words "no description supplied" in place of silence. ADR-0070 §8 refuses that unit at release, so
  the words mark a defect in a view cut before the gate existed.
- **AA-8. Language is declared** for the page (3.1.1) and for a passage in another language (3.1.2). A glossary term
  links to its entry in `narrative/glossary.md` as the unit binds it.
- **AA-9. Help is in the same place on every page** (3.2.6), and navigation keeps its order (3.2.3).

### 7. Conformance is to WCAG 2.2 at Level AA, and it is a dated audit ⟨K9⟩

**The target is WCAG 2.2, Level AA** *(drafter's choice of version and level; the custodian said "WCAG
Compliance")*. WCAG 2.2 is the W3C Recommendation in force and is ISO/IEC 40500:2025. WCAG 3.0 is a Working Draft
and is not a target.

- **WC-1. A release of the reader carries an accessibility conformance report**: a dated results file in the
  repository, cited by digest, which is never edited after it is written (ADR-0069 §6 G-1's rule for evidence). It
  names the reader's build by digest, the views and pages examined, both colour schemes, reading mode, each success
  criterion at A and AA with its result, and every known failure.
- **WC-2. The report has two parts, and only the second supports a claim.**
  - *Computed:* the output of pinned checkers over the pages examined. **A clean run refuses nothing and
    establishes nothing.** A failure refuses the release, by the ratchet ADR-0069 §10.2 uses, so that a failure that
    stood before the change does not block it and a new one does.
  - *Examined:* a person's audit against each criterion, with a keyboard alone and with at least two screen readers
    on two platforms, named with their versions. The person is named, and says whether they wrote any of the reader.
- **WC-3. A release says *checked* or *claimed*.** *Checked* means WC-2's examined part is complete for that build
  and was done by someone who did not write it. *Claimed* means anything less, and the reader's accessibility
  statement uses that word.
- **WC-4. The claim covers the reader and the content of the views named, together.** A unit with a defect of its
  own fails the page it is on. Content defects are reported against the unit (ADR-0070 §8), not waived as "content".
- **WC-5. Four AAA criteria are met in reading mode as advice**: enhanced contrast (1.4.6), visual presentation
  (1.4.8), unusual words (3.1.3) by way of the glossary links, and abbreviations (3.1.4). They are marked *advice* in
  the report and are no part of the claim.
- **WC-6. Another reader makes its own claim.** A deployment's or a third party's client (ADR-0071 §8) inherits the
  content's fields and nothing of this reader's report.

### 8. Degeneracy and the trusted base

**No degeneracy is declared, and no row is added.** No theorem takes a premise from a reader. A reader that fails
shows a page wrongly or not at all. What a person then does is bounded as ADR-0070 §11 says it is for the
documentation as a whole: by the admit path for a principal, and by the rules floor for a key-holder. A reader that
drops a status mark breaks RM-4 and ADR-0029 §3's rule for publications, and that is a defect in the reader and not
a change in any guarantee.

### 9. Ratification condition

- **The reader exists and serves every unit of ADR-0070 §3's set, in `latest` and in at least one checkpoint
  view**, from the service of ADR-0071. **Not met: nothing is built, and no unit is written.**
- **§1 is seen at the reference:** the reader runs against the public API with no other access, and a second client
  that is not this reader renders the same unit from the same API. **Not met.**
- **§3 to §6 are seen:** reflow at 320 CSS pixels and at 400% zoom; both schemes at LD-2's ratios; reading mode
  read, followed and printed with scripts off; the keyboard path through a unit, its three levels and its bindings.
  **Not met.**
- **A conformance report under §7 WC-1 exists for a named build**, with its computed part reproducible from pins
  and its examined part by a person other than the author. **Not met: no report, no auditor.**
- **The diagram generators emit a rendering for each scheme, and a long description for each diagram** (LD-4,
  AA-7). **Not met.**
- **ADR-0070 and ADR-0071 are ratified, or this record is ratified with them.** **Not met: both are Proposed.**
- **A reader who is not the drafter** (ADR-0029 A2). **Not met.**
- **The custodian's reading of every drafter's choice**, the WCAG version and level among them. **Not met.**

## Options considered

**The reader's framework and component library** ⟨K8⟩. One row is taken. Licences are as the drafter understands
them, and none was checked against its repository for this draft.

| Option | Disposition |
|---|---|
| **React with Material UI** (MIT) | **Taken** ⟨K8⟩. A large component set with theming by CSS variables and two colour schemes. Its accessibility is the library's claim, which is why M-1 and §7 do not rest on it |
| React with **React Aria** or **React Spectrum** (Apache-2.0) | Not taken ⟨K8⟩. Behaviour and accessibility without a visual design; the strongest record on assistive technology of the React libraries the drafter knows. It is the first replacement for any Material UI component that fails M-1 *(drafter's recommendation)* |
| React with **Radix** primitives or **Base UI**, styled in the repository | Not taken. Unstyled, accessible primitives. More to build, and less to override |
| React with **Chakra UI**, **Mantine**, **Ant Design**, **Fluent UI** or **Carbon** | Not taken. Comparable component sets. None was asked for, and none changes §3 to §7 |
| A public-sector design system: **GOV.UK Design System** or **USWDS** | Not taken. Each is built and audited for accessibility first, and is server-rendered HTML with little script, which is RM-1's shape. Neither is a React library, and each carries a government's look. Worth a second reading if the audits of §7 go badly *(drafter's recommendation)* |
| **Vue** with Vuetify, **Angular** with Angular Material, **Svelte** or **Solid** | Not taken ⟨K8⟩. Any of them can meet §1 and §3 to §7. Nothing in those sections is React's |
| **Web components** (Lit), published for embedding | Not taken as the reader. Kept as a way to meet ADR-0071 §8: a `<topak-unit>` element any page can host would be a second client, and would satisfy §9's second item |
| **Server-rendered HTML with no client framework** | Not taken ⟨K8⟩. It is what RM-1 already requires of every page. A reader that was only this would meet §3 to §7 with the least code, and would lose search-as-you-type and the level switch without a load |
| **A documentation generator**: Docusaurus, MkDocs with Material, Sphinx, Antora, Astro Starlight, VitePress | Not taken. Each builds a site from files at one commit. Versions are copies of the tree, which fits a few releases and does not fit ADR-0071 §2 and §4, where every revision and every checkpoint is addressable and equal. None serves an API another client could use ⟨K7⟩ |
| **The carrier's rendering** (Markdown on GitHub), as today | Not taken. It is what exists. It has no levels, no bindings, no views, and its accessibility is the carrier's |

**Other choices.**

| Option | Disposition |
|---|---|
| **WCAG 2.1 AA**, which most regulation still names | Not taken *(drafter's choice)*. 2.2 contains it, and adds focus not obscured, target size and consistent help, which a reader made of navigation and long text can meet |
| **WCAG 2.2 AAA throughout** | Not taken. The W3C does not recommend AAA as a general policy, because some content cannot meet all of it. WC-5 takes four criteria that suit reading |
| **Conformance by automated scan** | Rejected (WC-2). It would make a tool's silence an admit |
| **An accessibility overlay script** | Rejected. It changes what one reader's users get and nothing of the content, and it would be a third party's script on every page |
| **A client-rendered application** with no HTML until scripts run | Rejected (RM-1). Reading mode would depend on the largest part of the reader working |
| **The scheme in the address**, so that a link carries light or dark | Not taken (LD-1). The choice is the reader's, not the sender's |
| **A dark scheme only**, or a light one only | Not taken ⟨K9⟩ |

## Consequences

**Positive**
- **A person reads the same unit, with the same marks, on a phone, a wide screen, paper or a screen reader.**
- **Conformance is a file with a date, a build and a name**, and the word *claimed* is available for when it is
  not yet earned.
- **The reader can be replaced.** It holds no content and no privilege, so a deployment's own reader, or an
  embedded element, is a peer of it.
- **Reading mode costs nothing extra**, because it is the baseline the rest is added to.

**Negative**
- **Two schemes, reading mode and three levels multiply what an audit must examine.** WC-1 names them all.
- **Material UI is a large dependency with its own design language**, and M-1 expects to override parts of it.
- **A person's audit is slow and has to be repeated per release.** Between audits a release is *claimed*.
- **Every diagram needs a second palette and a long description**, and the corpus has many diagrams.
- **Server rendering is a running service**, where a generated site would have been files.

## Open obligations

- **The server-rendering framework for React.** RM-1 fixes that pages arrive as HTML and not which framework sends
  them. Not chosen.
- **The checkers of WC-2**, pinned, and their ratchet.
- **An auditor who did not write the reader** (WC-3).
- **A second palette and long descriptions from the diagram generators** (LD-4, AA-7), which touches
  `skills/generating-corpus-diagrams` and `diagrams/`.
- **Mathematics and TLA+ in a page.** A formula and a module excerpt need a rendering a screen reader can speak.
  Not designed.
- **Whether EN 301 549 or Section 508 is also claimed.** Each maps to WCAG at AA and adds requirements of its own.
  Not read for this draft.
- **Languages other than English.** AA-8 declares language; no translation is planned.
