# ADR-0057 — The corpus's specifications form a graph: layers are open, every edge is typed by what it leaves to a person, a guarantee carries its givens, and a theorem is inherited at the grade of its weakest edge

**Status:** Proposed · 2026.11.06
**Status note:** Confirmation required under **C2**, because §3 claims that every relation between two specification
artifacts the corpus relies on is an edge of the graph, which is an exhaustiveness claim; and **C4**, because it makes
three open-list items computed rather than found by a reader (G11 items 56, 90 and 103). **C1** does not apply: no
privileged path gains an obligation. **C3** does not apply on the drafter's reading: §5 states a grade as a family of
binary inventories, so ADR-0023 §2's "no partial credit" stands at every grade (finding 3 keeps the question for a
reviewer). **Nothing in this record changes a theorem, a premise or a verdict at the reference**: at the weakest
grade the inventory it computes is the one `spec/inventory.py` computes today (§5).
**Pending:** none.
**Deployment position:** Archetype. A method declaration, as ADR-0046 is: it says how the corpus relates its own
artifacts. How a deployment declares its graph against this one is ADR-0058's. One degeneracy (§12).
**Depends on:** ADR-0023 §2, §6 (inventory as premise loss; the declaration), ADR-0033 (the reference is evidence;
the drift obligation), ADR-0045 §1, §3, §5 (rows; rows as premise nodes; what runs is a row), ADR-0046 (TLC, TLAPS,
mutations and witnesses), ADR-0053 §5 R7 (derived premises; premise columns of kind `check`)
**Relates to:** ADR-0058 (the deployment's overlay), ADR-0049 §4 (checked or claimed: a two-grade instance), ADR-0029
A2 (the bootstrap reviewer: who reads), the archetype-evolution record (G6 item 7; unwritten), which owns the
versioning of the binding table and, with it, of this graph
**Closes:** nothing until ratified. On ratification: nothing closes, and three items become computed. Item 56's
"stage one is behind the tree", item 90's missing binding rows, and item 103's stale `mechanism/lean` each become a
stale or missing edge the checker of §8 reports, instead of a line a reader writes into a checkpoint.
**Carries a debt against:** ADR-0033 (the drift pins bind to clauses, §7) · ADR-0045 §3 (the binding table is read
beside the graph, §8) · ADR-0053 §5 (its derived premises become instances of edge premises, §4)

## Context

**Piskala's three levels describe edges, not projects.** The paper places a team on one line: *spec-first* (a spec
guides the first build and may be abandoned), *spec-anchored* (spec and code are kept in step, and tests fail when they
diverge), *spec-as-source* (code is generated and never edited). Read against the corpus, no single point fits. The
floor is run as written: spec-as-source. The admit decision is proved, of a transcription, to be a step of
`FloorComposition`: anchored by proof, stronger than the paper's anchoring by tests. `State::apply` is anchored by
trace replay. The operator path is anchored by tests named after `Operators.tla`'s properties and by no refinement
(I47). Workflows are, today, spec-first: `Mechanism.tla` does not model them and trace validation was not rerun
(I49; G11 item 56). The level is a property of the relation between two artifacts, and the corpus has many relations.

**The corpus already keeps those relations, in four places that do not know of each other.**
`mechanism/corpus-pins.sha256` pins 61 records and modules the reference follows, whole-file, and `drift.rs` fails when
one moves. `spec/theorem-premise-binding.md` and its JSON bind every checked property to the rows and premises it
rests on, and `spec/inventory.py` evaluates them, with derived premises since ADR-0053 R7. `manifests/` measures each
cut by digest. `spec/proof-sync.sh`, `tools/lean-sync.sh` and `spec/mechanism-trace-results.sh` each report their own
kind of staleness. Each answers part of "what discharges what, and is it still in step", and none answers it whole.

**The relations already have strengths, and the corpus already names some of them as premises.** ADR-0053 R7 made
`invariant(M)`, `enc-faithful(M)`, `model-faithful(apply/Seats)` and `refines(Seats)` premises: the strength of an
edge, stated as what the theorem then rests on. ADR-0049 §4 marks each field of an allowlist entry *checked* or
*claimed*. T-0045-28, "the running code refines the checked specification", is a trust-root row standing exactly
where an edge from the code to the modules would be, and it sits in every theorem's BASE.

**Three gaps follow from keeping them apart.** A pin says the far end moved, not what the edge was; `drift.rs` says
so of itself ("checks that the pinned spec has not moved, not that the code follows it", ADR-0045 T-0045-28, struck
and kept). A pin is whole-file, so a History row trips it as a changed clause does. And a guarantee stated twice,
the operator envelope in Cedar for the decision and in Rust for apply, is tied by tests alone, and nothing lists the
places where that is so (I47 (e)).

## Decision

### 1. The graph's nodes are artifacts, and its layers are open ⟨K1⟩ ⟨K3⟩

A **node** is an artifact that states something normative or checks something stated: a record's clause, a module,
a proof module, a Lean file, a floor stage, a Rego policy, a crate or a function in it, a schema. It is named by its
path, and a record's clause by its record and section (§2). Its content is identified by digest.

Each node carries a **layer**, a label for reading, from a set that is open. A new kind of artifact is given a layer
name when it first enters the graph, and no record is needed to add one *(drafter's choice: a layer carries no
premise; only edges do, §4)*. The corpus starts with the layers it has:

| Layer | What it holds in the corpus |
|---|---|
| intent | The ToO's principles and threat model; ADR-0025's intent, "the sole axiom" |
| vocabulary | `narrative/glossary.md` |
| record | `decisions/`, and the checkpoint that is the state of record |
| assurance | ADR-0045 Annex A and B; the binding table; the residual-risk statement |
| model | `spec/*.tla`; the proof modules; `spec/lean/` |
| interface | Schema S; the allowlist entry (ADR-0049); every format the format inventory lists |
| policy | `floor/` and its stages; `policies/` |
| implementation | `mechanism/` crates; `mechanism/lean/`, as a transcription of them |
| runtime | Recorded traces; the trace-validation results |
| deployment | A deployment's declaration (ADR-0058) |

The graph has no name beyond its description, *the specification graph* ⟨K3⟩.

### 2. A record's guarantees are numbered, and each carries its givens

The binding point of the graph above the model layer is the **clause**: a numbered subsection of a record's Decision,
with its inline amendments, cited as the corpus already cites it ("ADR-0031 §4, A1"). Records are append-only with
typed History rows, so a clause's number is stable. A clause may number its guarantees `§n.k` where it states more
than one.

**A record drafted after this one gives each clause four parts**, in this order *(drafter's choice of the fourth name;
the custodian proposed "gates")*:

- **Goal.** One sentence: why the clause exists. Not normative, and not bound.
- **Givens.** What the guarantees rest on: rows, parameters, derived premises and other clauses, by id. "None beyond
  BASE" is a claim, stated as one.
- **Guarantees.** The normative statements, numbered.
- **Discharge.** The edges that discharge each guarantee (§3), with their types, or "none yet", stated as a claim.
  Named *discharge* and not *gate* because the corpus already has floor gates (ADR-0030 §5) and promotion gates
  ("gates enable voting; they do not vote"), and the record's own gate is its Ratification condition.

**Records already ratified are not rewritten.** Their givens are read from the binding table, which already holds
them as each row's premises, and their discharge from the graph. A clause gains the four parts when an amendment next
touches it.

### 3. Every edge is typed by what it leaves to a person ⟨K2⟩

An **edge** runs from a lower node to the node it discharges, and says how. Its **type** is one of eight, ordered by
what the edge leaves to a person, strongest first *(drafter's choice: a total order; finding 4)*:

| Type | The lower node | What the edge leaves | In the corpus today |
|---|---|---|---|
| **executed** | Is the higher, run as written | The engine that runs it (a row) | The linked floor stage, pinned by digest (`PINNED_*_SHA256`); Cedar on T-0045-3 |
| **generated** | Is produced from the higher by a pinned tool and not edited | The generator | The floor stages, built by `floor/proposed/build.py` from the genesis files |
| **proved** | Is related to the higher by a machine-checked proof between two formal artifacts: implication, refinement, or equal state graphs | The prover or kernel (a row) | Proof modules to their modules (T-0045-31); the graph check of the `Seats`, `FloorComposition` and `Emergency` encodings (T-0045-37) |
| **proved of a reading** | Is proved, but one end is a hand transcription or a model of the other | The reading (`enc-faithful`, `model-faithful`), which a check may support | `mechanism/lean/` `Admit.lean`, `Clock.lean`, `FloorRefinement.lean`, `SeatsModel.lean` |
| **replayed** | Has its recorded behaviour replayed through the higher, step by step | The paths no trace reached | The reference's traces through `spec/Mechanism.tla` and `spec/ConfinementRefinement.tla`; the Lean replays |
| **tested** | Passes tests named after the higher's properties | The inputs no test chose, and whether the tests state the properties | `Operators.tla` and the reference (I47); the floor gates' case suites |
| **read** | Was written against the higher and read by a person | The reader | Every module against its record; the Rust against its records; the narrative |
| **trusted** | Has no edge; a row stands where the edge would be | The row | T-0045-28, for every theorem whose route reaches the code |

**A citation is not an edge.** A record citing another, or code citing a record in a comment, discharges nothing; it
is how a reader finds the edge.

**A read edge names its reader.** A reading by the drafter and a reading by someone else are the same type, and the
graph shows which it was, because ADR-0053 R1(b) and ADR-0029 A2 already distinguish them. Mutations and witnesses
(ADR-0046) support a reading of a record by a module: they show that the module tells the clause from its negation,
not that it reads the clause rightly. They do not change the edge's type.

**An edge is fresh or stale.** It pins the content of both ends, by clause for records (§7) and by digest otherwise.
An edge whose pin no longer matches is **stale**, and is re-pinned by the review `drift.rs` already asks for: read the
change, bring the lower node into line or register why not, then re-pin.

### 4. Each edge contributes a named premise, and the binding reads it

An edge of type *t* from *x* to *y* contributes the premise **`edge(t, x → y)`**, a premise column of kind `check`
(ADR-0053 R7) whose value is the edge's freshness and, where the type has a results file, that file's verdict. **A
stale edge's premise is false**, as a `check` premise is false today when its results file is out of step with the
tree. An absent edge's premise is false, as an undeclared row is (ADR-0045 §3, rule 1).

ADR-0053's derived premises become instances, and nothing they compute changes:
`invariant(M)` is T-0045-31, or T-0045-37 with `edge(proved of a reading, encoding(M) → M)`; `refines(Seats)` is
T-0045-28, or the route through `SeatsModel`. **T-0045-28 becomes a derived premise for every theorem whose route
reaches the code**: the row, or any route of edges from the implementation to the module. Today the row is the only
route for every theorem but the two of `Seats`, so no verdict moves.

**An edge is added with its premise in the same commit**, and `inventory.py --check` passes before it lands, as the
binding table's own rule already requires of a premise change.

### 5. A theorem is inherited at a grade, and each grade is a binary inventory ⟨K2⟩

A **grade** is an edge type used as a threshold. **The inventory at grade *g*** is ADR-0023 §2's inventory computed
with every edge premise of a type weaker than *g* set false. A theorem **holds at grade *g*** when it is present in
that inventory. **Its grade** is the strongest *g* at which it holds: over the routes that hold, the strongest of each
route's weakest edge. Rows, parameters and gap premises hold or fail as today, and do not grade.

**At grade *trusted* the inventory is the one the corpus computes today.** Raising the grade can only void a theorem,
never revive one, because the evaluation is still AND and OR (ADR-0045 §3). ADR-0023 §2 holds at every grade: a
theorem is present or absent, and there is no weaker version of it. What a grade adds is the strongest evidence under
which it is present.

**A theorem is graded on its way down** *(drafter's choice)*. Its grade is taken over the edges from the layer it is
stated at to the layer that runs: from a module to the code for a mechanism theorem, from a floor stage to the engine
for a floor theorem. **The edges up, from a module to the record it reads, are graded once per module** and reported
beside the inventory, not folded into each theorem. Every one of them is *read* today, by the drafter (finding 5), so
folding them in would set every theorem's grade to *read* and say nothing that one line does not.

### 6. A guarantee stated twice is two nodes and an edge between them

Where one guarantee is stated in two artifacts, the graph holds both and the edge between them, typed. The operator
envelope (I47 (e)) is a Cedar node and a Rust node with a *tested* edge. **The checker lists every such pair with its
type**, so that each is raised, by generating one from the other or by proving them equal, or kept, with the type
showing. Raising one is not this record's obligation; listing them is.

### 7. Pins bind to clauses

The drift pins move from whole files to clauses for records: the pin of a record is the digest of each clause the
reference follows, by section, with its inline amendments. A History row, a status line or a pending amendment that
is not yet inline changes no clause and trips no pin. Modules, floor files and code stay pinned by file. The rule
`drift.rs` states, that every record or module the code cites is pinned, is kept, read by clause. This is a debt
against ADR-0033 (an addendum), not a change to it.

### 8. One graph, and the four lists are read against it

The graph is one machine-readable file under `spec/`, of nodes and typed edges, each edge with its pins and its
evidence by digest. **A checker computes from it**: every stale edge; every clause with guarantees and no discharging
edge; every twice-stated guarantee (§6); and, through `inventory.py`, the inventory at each grade with each theorem's
grade and the route that carried it.

**The four lists are checked against it first and generated from it later** *(drafter's choice: nothing that works
today is replaced by something that does not yet)*. `corpus-pins.sha256`, the binding JSON's `check` columns, the
manifest index and the sync scripts' file lists each gain a check that they agree with the graph. The binding table
stays canonical for its row premises, as `inventory.py --check` already makes it.

### 9. Interfaces are a layer, and a format gains a schema node when a record next touches it

The format inventory found the corpus's formats defined in prose by the records, typed in part by schema S, and in
part existing "only in `mechanism/`" and cited by no record. **A format gains an interface node, with a
machine-readable schema, when a record next touches it** *(drafter's choice: not a sweep)*: JSON Schema for a lease,
an allowlist entry, a tool result; AsyncAPI for a topic and its records. Its edges run to the clause that defines it
and from the code and the floor that read it.

### 10. The method of an edge is the corpus's choice, and its type is not

Which formalism states a node is chosen by the kind of property, not by the domain: a distributed protocol in TLA+, an
authorization in Cedar, a functional core in Lean, a data shape in a schema. **Some components cannot be specified,
and the architecture keeps them outside the verified object** (ADR-0007; ADR-0016): the graph holds them as nodes with
no edge below the record, so that every theorem that would need one is computed void rather than assumed. A method new
to the corpus enters with its toolchain row (ADR-0045 §4); the type of its edges is read from §3's table by what the
edge leaves, whatever the tool.

### 11. The corpus against this record: what it does, should do and could do ⟨K5⟩

| | Does | Should (this record) | Could (not decided here) |

### 13. The trusted base

**No row is added.** The checker of §8 decides no admit, promotion or issuance; its failure can misstate a grade, which
is a claim about evidence and not an addition of authority. It is read as `inventory.py` is: "the verdict is only as
good as the declaration", and a grade only as good as the graph.

## Options considered

| Option | Disposition |
|---|---|
| **Place the project on Piskala's line** | Rejected. The corpus sits at five points at once (Context); the level is the edge's |
| **One record for the corpus and adopters together** | Not taken ⟨K4⟩. The method is the corpus's; what a deployment declares is an interface, and ADR-0058 holds it formalism-neutral |
| **A tree of specifications** | Rejected. One clause is read by several modules and one module reads several clauses |
| **A fixed set of layers** | Not taken ⟨K1⟩. A layer carries no premise, so adding one costs nothing the computation sees |
| **Holds or void, no grades** | Not taken ⟨K2⟩. It hides the difference between a theorem carried by a proof and one carried by a trust root, which is the difference T-0045-28 exists to name |
| **Grades as partial credit on a theorem** | Rejected. ADR-0023 §2. A grade is the threshold at which a binary inventory is taken (§5) |
| **A partial order of edge types** | Not taken now *(drafter's choice)*. A total order gives one grade per theorem; finding 4 names where it may fail, and ADR-0023 §5's per-axis precedent is the way out |
| **"Gates" as the clause's fourth part** | Not taken *(drafter's choice)*. The word is taken twice in the corpus (§2) |
| **Pinned as an edge type** | Rejected. A pin detects change at the far end; it says nothing of the relation. Freshness is an attribute of every edge |
| **Generate the four lists at once** | Not taken *(drafter's choice)*. Check against the graph first (§8) |
| **A brand name for the graph** | Not taken ⟨K3⟩ |

## Consequences

**Positive**
- **The corpus can say how strongly each theorem reaches the code**, not only whether its premises are declared.
- **Staleness is computed.** What G11 lists by hand at items 56, 90 and 103 the checker reports.
- **History rows stop tripping the drift test**, and a changed clause still does.
- **Twice-stated guarantees are listed**, with the type of the edge that ties them.
- **Adopters get an interface** (ADR-0058) built on what the corpus already does, not on a new method.

**Negative**
- **One more artifact to keep in step**, with its own checker, beside four it does not yet replace.
- **The total order may be wrong in places** (finding 4), and every grade inherits the error.
- **Grades will look worse than the prose.** Most mechanism theorems grade *trusted* today, which is true and has
  been stated only in T-0045-28's note.
- **One author, one day**, as every record since G2.

## Findings

1. **The paper's levels are properties of edges.** Spec-as-source is the floor's edge; spec-anchored by proof is the
   admit decision's; anchored by replay is `apply`'s; anchored by tests is the operator path's; spec-first is the
   workflow path's, for now.

9. **The drafter's choices in building** ⟨R1⟩. (a) *Pins.* §3 pins both ends of an edge. An edge with no results
   file whose lower end is the reference (a read edge from the code) or a row (a trusted edge) pins its upper end
   only, as `corpus-pins.sha256` does. Pinning both ends would make every commit to the code stale 139 read edges
   and every trusted edge, and so void the inventory at grade *trusted*. An edge with a results file pins what the
   file records, so a change to the code does make it stale. (b) *Clauses.* A record without a Decision section is
   one clause, `text`. An unnumbered subsection of a Decision is a clause, named by its heading. Annexes, and
   ADR-0033's `## 7.`, are clauses. An amendment drafted as its own pending subsection is left out of its clause.
   Pending text marked inline in a clause stays in it, since the reference may follow it before it is in force, as it
   follows ADR-0054's. A citation of a record without a section reads every clause of it. (c) *Evidence that spans a
   package.* `Admit-results` names every file `mechanism/lean` transcribes, and each of its four edges pins all of
   them, as `lean-sync.sh` reads the series; an encoding under `spec/lean` pins only what it imports. (d) *Types.*
   The graph check is *proved*, as §3's table has it. The Lean proof of an encoding is *proved of a reading*, and
   where nothing checks the encoding, its reading is a read edge carrying `enc-faithful(M)`. (e) *Theorems no module
   states* are stated at the nodes `STATED_AT` names in the builder: ADR-0015, ADR-0024, ADR-0033 §2, the linked
   stage, and the two trace modules.
10. **Every module's edges up are *read*, by the drafter** ⟨R1⟩: all 31 modules. This is finding 5, computed.
11. **Fifty-one clauses of twelve records the reference follows have no edge but the code's reading** ⟨R1⟩. No
    module, floor stage, proof or check reads them. They include every clause of ADR-0016, ADR-0035 and ADR-0044, and
