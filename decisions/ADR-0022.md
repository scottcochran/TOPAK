# ~~ADR-0017~~ ADR-0022 — Typed action alphabet for Build principals ⟨N1⟩

**Status:** Accepted (genesis) · 2026.09.23 — **§1–§5, §7, §8 only** ⟨B2⟩

undelivered, so every Build containment theorem stays conditional on it and Build principals are

## Context

ADR-0007 holds that semantic judgment is never a lift: `Contain` enforces a syntactic envelope
over a finite, totally-extracted action alphabet, and everything semantic is Observer detection.
Two later results lean on that alphabet directly. ADR-0010 makes `bundle ⊑ floor` a Build-time
obligation and calls it decidable *because* the alphabet is finite and total. ~~ADR-0016~~ ADR-0021 ⟨E1⟩ gives
Build an Observer and a typed emission stream, and cannot be implemented without one.

Run has such an alphabet. Build does not. Build principals currently write files, invoke
toolchains, and open promotion requests in an untyped, developer-shaped environment, which means
`Build(Contain)` from ADR-0002 is presently a claim about a membrane with no declared surface.

**The real question is narrower than "what are the action types."** It is whether a Build agent
is `Contained` or `Mediated` under ~~ADR-0005's split~~ the `Contained`/`Mediated` split (Theory of Operation 09.12 §5) ⟨E2⟩. `Contained(p)` claims effect exclusivity —
the principal reaches the world only through the alphabet. A principal with a shell, a package
manager, network egress, or a git remote does not satisfy that under any typing, because the
alphabet would not be *total*: effects exist that no action names. In that case Build agents are
`Mediated`, Build's safety theorems do not quantify over them, and `Build(Contain)` is an
attribution claim rather than a containment claim.

Moon & Varshney's verified instance is the reference shape: a four-variant `Action` enum, a
workspace root, a tool allowlist, and a loop bound. Small is the point. The alphabet's size is
what makes the floor reviewable by a human at deploy cadence, which is the entire basis for
trusting the Build HITL gate under ADR-0010.

## Decision

**A ~~five-variant~~ six-variant ⟨N2⟩ alphabet, three mechanism parameters, and one explicit obligation this record
does not discharge.**

### 1. The alphabet

Egress only. The alphabet types what a principal *does*, not what it receives; task delivery and
corpus content are environment steps.

| Variant | Meaning | Envelope constraint |
|---|---|---|
| `Read(ref)` | Resolve a content-addressed object | `ref` inside the pinned corpus root |
| `Draft(target, content)` | Write a candidate into the round workspace | `target` inside the round-scoped workspace |
| `Invoke(tool, inputs)` | Run an allowlisted verification tool | `tool` allowlisted by name **and** digest; `inputs` workspace-resident |
| `Emit(record)` | Append to the principal's round topic | Per ADR-0021; own topic, current epoch |
| `Submit(digest \| ⊥)` | Offer the sealed workspace **for promotion (ADR-0024)**, or abstain | Terminal for the authoring round |
| **`Vote(verdict, digest, evidence, rulesEpoch)`** | Cast a promotion vote | Seat held at `rulesEpoch`. `verdict = grant` only from a grant seat. Not the artifact's author — a mechanism constant, not an issued value ⟨R2⟩. Terminal for the voter's promotion round. |

⟨R1⟩ Table replaced; the five-variant table, after E1, is under History.

~~Five variants, not four:~~ Six variants, not four (`Vote` added 2026.09.15; see §7) ⟨N2⟩: TOPAK needs `Emit` as a first-class action because ~~ADR-0016~~ ADR-0021 ⟨E1⟩ makes the
stream the Observer's substrate rather than an implementation detail of logging.

### 2. Every action carries epoch and lease

Actions taken under a fenced epoch are rejected by the mechanism, not by policy. Identical
discipline to Run; no new machinery.

### 3. Three parameters

- **Corpus root** — a pinned, content-addressed set. `Read` is scoped to it, which is the
  syntactic control over ingress. Whether the corpus is *poisoned* is an Observer finding, not
  an enforcement decision; the envelope governs where a principal may read from, never what the
  content means.
- **Tool allowlist** — name plus digest. Each entry carries a hermeticity obligation: no network,
  no filesystem outside the workspace, deterministic given its inputs.
- **Round bound** — maximum actions per round. Termination, and it bounds the state space.

### 4. Finite in variants, not in instances

`Read(ref)` ranges over a large ground set. Refinement under ADR-0010 must therefore be decided
over **variants with symbolic parameters** — Rego predicates on action type plus reference
prefix, checked by SMT — not by enumerating instances. Stated explicitly because "the alphabet is
finite" is true in a sense that does not by itself make `bundle ⊑ floor` terminate.

### 5. Shared core, domain extensions

`Read`, `Emit`, and the epoch/lease carrier are common to Build and Run. The remaining variants
are domain-specific. See Consequences for what this does to ADR-0010's single shared floor.

### 6. Confinement is an obligation, not an assumption

The mechanism must admit no residual channel: no shell, no network egress, no filesystem access
outside the workspace and corpus root, no path into the artifactory except `Submit`. **This
record states the obligation and does not deliver it.** Until a mechanism enforces it, Build
principals are `Mediated`, and every Build containment theorem should be written as conditional
on this obligation being discharged.

### 7. Seat-level separation ⟨R1⟩

Per artifact, the principal holding `Submit` and the principals holding `Vote` are disjoint
(ADR-0024 author recusal). Within a single promotion round, `Vote` excludes `Draft`, `Invoke`,
and `Submit`. Voters review; they do not author.

**Recusal is enforced here, and only here** ⟨R2⟩. The envelope refuses an author's vote, so no
issuance can admit one. ADR-0026 R3 was withdrawn on that ground (S6-3): a value the mechanism fixes
cannot be bounded by a floor entry, and R3 tested a parameter that the envelope had already removed.
~~The cost is that relaxing recusal is now a mechanism release rather than an issuance, which is the
same trade the corpus already takes for "a timeout is never a grant."~~ *The envelope is stated in
the policy floor (ADR-0030, B7), so relaxing recusal is a policy-floor relaxation: an anchor
issuance and a promotion (ADR-0030 §5). That is stricter than a mechanism release, and
monotone-safe.* ⟨A1⟩ No degeneracy on the board asks for it.

### 8. Anchor actions are not Build actions ⟨R1⟩

`Issue` and `Resign` belong to the trust anchor's alphabet (ADR-0025). They are environment
events, not `Contain` actions, and no Build principal can express them.

## Consequences

**Positive**

- Unblocks ~~ADR-0016~~ ADR-0021 ⟨E1⟩; gives the Build Observer something typed to read.
- Makes `bundle ⊑ floor` decidable in Build in the way ADR-0010 already assumes it is.
- ~~`Submit` as the sole terminal action makes the promotion gate the only egress from Build,~~
  The only egress from Build is `Submit` followed by `Vote(grant)` from the grant seats the issued
  quorum requires — every counted seat at the archetype, `rules.quorum = "all"` (ADR-0024 §2,
  ADR-0026 R1) ⟨R2⟩ — and no
  `Vote(deny)` from veto seats. Egress is a sequence of two typed actions by disjoint principals.
  That replaces trust in one signer with a checkable property of the action log ⟨R1⟩,
  which is what ~~ADR-0016's~~ ADR-0021's ⟨E1⟩ signature-over-provenance needs in order to mean anything.
- The alphabet is small enough to review at deploy cadence, satisfying ADR-0010's minimality
  argument on its own terms rather than by assertion.
- Six variants remain reviewable at deploy cadence. The minimality argument still holds. ⟨R1⟩
- `Vote` is the first variant whose envelope depends on rules-floor state (seat at epoch; ADR-0026).
  This makes refinement in Build depend on the rules floor as well as the policy floor. ⟨R1⟩

**Negative**

- **`Invoke` is the whole attack surface.** A tool allowlist is only as strong as its weakest
  entry; one allowlisted tool with a shell or a network socket collapses the alphabet to a single
  variant and makes the envelope vacuous. This is the exact shape of the vacuous-floor failure,
  relocated. The per-tool hermeticity obligation is currently unowned, and it wants either an
  owner in ADR-0014 or a gate alongside floor fitness. *For tools packaged as Wasm components it is discharged by
  ADR-0034 P4, by construction; for native tools it stays unowned, and using one is D-0034-3* ⟨B10⟩.
- **This alphabet is not how agents author code today.** No shell, no package installation, no
  network, no git. Build principals under `Contain` cannot use general-purpose coding harnesses.
  That is a real capability cost and should be stated in the article rather than discovered by a
  reader who has used one.
- The confinement obligation in §6 makes the sandbox gap non-deferrable. It was previously a
  stated weakness; it is now a named precondition of a ratified structural claim.

**Bearing on an open question**

ADR-0010 specifies **one floor, shared by Build and Run**. A single floor over two partially
disjoint alphabets is either vacuous on the variants a domain lacks, or it is two floors sharing
a name. Neither is what 0010 intended. This is direct evidence on the open "global floor versus
per principal class" question and it points at **per class** — Build and Run principals have
different alphabets, so they need different floors sharing a verified core. Recommend carrying it
into ADR-0014 rather than resolving it here.

**Requires follow-up**

- Seat-level scoping: whether all four LTRO seats in Build draw from the whole alphabet or a
  subset each. A Reader with `Draft` authority erases Build's internal separation of duties.
  **Partially resolved** by §7 for voters; LTRO seat scoping for authors is unchanged. ⟨R1⟩
- Whether the Build and Run Observers read one alphabet or two, which follows from §5.
- Whether `Draft` and `Invoke` records fall on the control-plane or cognitive-payload side of
  ADR-0004's partition. `Invoke` looks like control plane with a cognitive payload attached,
  which is the case 0004 handles least clearly.
