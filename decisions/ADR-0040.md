# ADR-0040 — Run has its own alphabet: `Consult`, `Actuate` and `Report`, and it shares only the carrier with Build

**Status:** Proposed · 2026.09.29
**Status note:** On ratification, confirmation required under **C3** (it reverses in effect ADR-0022 §5's sentence
that `Read` and `Emit` are common to Build and Run) and **C4** (it resolves the debt ADR-0030 carries on its face, and
ADR-0033's and ADR-0039's open obligations that wait on it). C1 and C2 do not apply to this record: the privileged
path is restated in ADR-0041 §3, and Run's confinement claim is ADR-0042 §6. **This record names variants and assigns
obligations. It discharges none of them.**
**Pending:** none.
**Deployment position:** Archetype. No degeneracy is declared here; each obligation's degeneracies are on the record
that owns it (§6).
**Depends on:** ADR-0015 (the two effect classes), ADR-0007 (syntactic lift only), ADR-0022 §2 and §4 (the carrier;
finite in variants, not in instances), ADR-0031 §1 (the lease's `alphabet` field), ADR-0018 (the validator is total
over the alphabet), ADR-0010 (`bundle ⊑ floor`)
**Relates to:** ADR-0041, ADR-0042, ADR-0043 (the three obligation records) · ADR-0037 §4 (alphabets by seat kind) ·
ADR-0039 (coupling) · ADR-0034 (the Run profile) · ADR-0009 and ADR-0013 (break-glass) · ADR-0014, reserved (one floor
or one per class)
**Closes:** nothing yet. On ratification: G5 item 13; ADR-0030's debt "a record for Run's alphabet"; ADR-0033's open
obligation of the same name; `mechanism/` G3. It unblocks G5 item 26 (the Run profile) and does not close it.
**Carries a debt against:** ADR-0022 (§5, an amendment: the carrier is shared, the variants are not) · ADR-0037 (§4's
Run column, a dependent entry) · ADR-0033 (an addendum: the renames under `mechanism/`) · `floor/` and `policies/`
(the renames; both DRAFT) · ADR-0018 (decoder–alphabet compatibility, G5 item 17, which a rename triggers)

---

## Context

**No record defines Run's alphabet.** ADR-0022's Context says "Run has such an alphabet. Build does not." ADR-0030 §10
finding 4 found the first half unsupported: ADR-0015 gives Run two effect classes and nothing names their variants.
Since 2026.09.24 two provisional actions, `RunInvoke` and `RunEmit`, have carried those classes in the draft floor,
the reference and the bundle tier, each marked provisional. The position has inverted: Build has a ratified alphabet,
and Run has a placeholder.

The placeholder has three defects, and a record that only blessed it would ratify all three.

- **It has no ingress.** ADR-0037 §2 says the Listener delivers "the admitted `Read` content" to the Thinker. Run
  admits no read. `RunCtx` carries a `corpusRoot` that no Run policy consults, so the schema expected a variant the
  alphabet never had.
- **It borrows a verb it cannot honour.** Build's `Invoke` runs a verification tool under a hermeticity obligation: no
  network, no filesystem outside the workspace, deterministic given its inputs (ADR-0022 §3). A Run tool exists to
  have an effect. `RunInvoke` takes the name and cannot take the obligation.
- **It contradicts an accepted section.** ADR-0022 §5 says `Read`, `Emit` and the carrier are common to both domains.
  The floor scopes `Read` and `Emit` to `principal.domain == "build"` and gives Run a separate emission. Nothing
  reconciles the two.

**Small is still the point.** ADR-0022 took Moon & Varshney's shape: a handful of variants, a root, an allowlist, a
bound. The alphabet's size is what makes the floor reviewable at deploy cadence. Run keeps that shape. What differs
between the domains goes into obligations, and each obligation gets a record that owns it.

## Decision

### 1. The alphabet

Run principals act through exactly three variants.

| Variant | Meaning | Envelope constraint | Class under ADR-0015 |
|---|---|---|---|
| `Consult(ref)` | Resolve a content-addressed object | `ref` resolves inside the pinned Run root (§3) | **Ingress.** Not an effect: nothing crosses outward |
| `Actuate(tool, inputs)` | Invoke an allowlisted Run tool | `tool` is allowlisted by name **and** digest, and its entry declares the channel it opens (§3) | **Effect:** tool invocation |
| `Report(record)` | Append to the principal's round topic | The topic is the principal's own, of the current epoch and round, and unsealed | **Effect:** principal emission |

**ADR-0015's effect set is unchanged.** `Actuate` and `Report` are its two classes, one variant each. `Consult` adds a
variant and no effect, as `Read` and `Draft` do in Build.

**A read of live state is an `Actuate`.** Anything not content-addressed in advance is reached through an allowlisted
tool, however read-only the tool is, because the request itself leaves the membrane. `Consult` never reaches a source
that can observe it being read. This one line is what ADR-0041 §2's exemption rests on.

**The provisional names are retired.** `RunInvoke` becomes `Actuate` and `RunEmit` becomes `Report`. `Consult` is new.
The `Run` prefix is dropped because the domain is already a fact about the seat (`Seat.domain`, ADR-0037 §1).

### 2. The carrier is shared; the names are not

Every Run action carries epoch and lease, and an action under a fenced epoch is rejected by the mechanism and not by
policy. This is ADR-0022 §2, unchanged and common to both domains.

**No variant name is common to Build and Run.** A name that appears in both alphabets must carry the same obligations
in both, or a reader of one floor entry will assume the other's. `Read` is pinned in both domains, and is still not
shared, so that a floor entry, a lease's `alphabet` and a log line each name their domain without a second field
*(drafter's choice)*. ADR-0022 §5 is amended to say so; the amendment is a debt of this record.

### 3. Three parameters

- **Run root**: a pinned, content-addressed set, as Build's corpus root is. `Consult` is scoped to it. Whether its
  content is poisoned is an Observer finding and not an enforcement decision (ADR-0022 §3, carried over).
- **Tool allowlist**: name plus digest, and for each entry **the effect channel it opens**, declared. A Run tool is
  not hermetic and is not asked to be. It is asked to open the channel it declares and no other. Who checks that is
  ADR-0042 §6's obligation.
- **Round bound `R`**: the maximum number of admits in a round, counted over all three variants. It is a mechanism
  parameter, per domain (ADR-0039 §1; `mechanism/` I21). Its number is still a placeholder.

### 4. There is no terminal variant

Build's round ends at `Submit`. Run has nothing to offer a gate, so it has no terminal action. **A Run round ends when
its lease ends**, and ADR-0042 §5 says what that means for the seal. A principal that has finished its task holds its
lease until it lapses.

### 5. Finite in variants, not in instances

`Consult(ref)` and `Actuate(tool, inputs)` range over large ground sets. `bundle ⊑ floor` is decided over variants
with symbolic parameters, never by enumerating instances. This is ADR-0022 §4, carried over. It is why tool arguments
are parameters of one variant and not variants of their own.

### 6. Every obligation has an owner

The alphabet is minimal because its constraints live elsewhere. Each one is named here with the record and section
that owns it, so that none is left on the open list with no owner, as ADR-0022 §6 was.

| Obligation | Scope | Owner |
|---|---|---|
| One envelope per variant, stated in the floor | Policy | ADR-0041 §1 |
| Coupling to a live Observer covers effects and not `Consult` | Policy | ADR-0041 §2 |
| Break-glass reaches `Actuate` and nothing else | Policy | ADR-0041 §3 |
| The bundle tier narrows tools and arguments, and only subtracts | Policy | ADR-0041 §5 |
| The validator is total over the three variants | Mechanism | ADR-0042 §1 |
| The sequence counts effect-bearing admits | Mechanism | ADR-0042 §2 |
| Every `Actuate` leaves a record on the round topic | Mechanism | ADR-0042 §3 |
| A tool's result is ingress and is recorded | Mechanism | ADR-0042 §4 |
| The round seals when the lease ends | Mechanism | ADR-0042 §5 |
| Confinement: no channel but the front door | Mechanism | ADR-0042 §6, stated and not delivered |
| What the Listener delivers | Cell | ADR-0043 §1 |
| Alphabets by seat kind | Cell | ADR-0043 §2 |
| The decoder targets this alphabet | Cell | ADR-0043 §3 |
| The Observer reads every record the mechanism writes, to the seal | Cell | ADR-0043 §4, §5 |

### 7. Ratification condition

- **The amendment to ADR-0022 §5 is drafted**, marked inline as pending, and ratified with or before this record.
- **The draft floor names the three actions** and passes ADR-0030 §5's gates under ADR-0041 §7.
- **The reference's front door exposes three tools to a Run seat and nothing else**, under these names, with an
  ADR-0033 addendum recording the run.
- ADR-0041, ADR-0042 and ADR-0043 need not be ratified first. This record assigns their obligations; it does not rest
  on their discharge, and ADR-0042 §6 in particular may stay Proposed after the rest is accepted.

## Options considered

| Option | Disposition |
|---|---|
| **Keep `RunInvoke` and `RunEmit`, and add `RunRead`** | Not taken. The custodian's first proposal, set aside by the custodian for its names. The prefix repeats the seat's domain, and `RunInvoke` implies Build's hermeticity |
| **Share `Read` and `Emit` with Build**, as ADR-0022 §5 reads | Rejected. The floor already scopes both by domain, and Run's emission carries a coupling (ADR-0039 §2) that Build's does not. One name with two sets of obligations is the defect this record removes |
| A fourth, terminal variant | Not taken (§4). Run offers nothing to a gate. Ending a round early is a lease operation if it is anything, and ADR-0042 records it as not taken |
| `Consult` over live sources | Rejected (§1). A live read is egress. It would need coupling, and the exemption in ADR-0041 §2 would fall |
| No `Consult`: all ingress through tools | Rejected. Every read would be effect-bearing and coupled, and the Listener's claim that ingress is exactly the admitted reads would have no variant under it |
| **A wire-level vocabulary**: MCP method plus tool-name matchers, as in OpenShell's `protocol: mcp` rules | Not taken at the archetype. It filters a channel to a server the mechanism does not own, names tools by string with no digest, and matches no arguments. It is the natural shape for a degenerate rung at which ADR-0034 P1 is not met, and is left to that declaration |
| An expression language over call arguments as the vocabulary | Not taken. Arguments are parameters of `Actuate` under §5. Constraints on them belong to the bundle tier (ADR-0041 §5) |

## Consequences

**Positive**
- **G5 item 13 gets a record**, and the floor's Run half, the reference's Run half and ADR-0037 §4's Run column stop
  being provisional once it is ratified.
- **Run gains a named ingress**, so ADR-0037 §2's Listener has something to deliver.
- **Each name carries one set of obligations.** A reader of a floor entry or a log line knows the domain from the
  verb.
- **Three variants remain reviewable at deploy cadence.** ADR-0010's minimality argument holds for Run on the same
  terms as for Build.
- **The per-class floor question (G5 item 9) gains evidence.** With no shared variant, what the two floors share is
  the carrier and the seat-kind carve-outs, and nothing else.

**Negative**
- **An accepted section is reversed in effect** (ADR-0022 §5), which is C3.
- **`Actuate` is the whole attack surface**, as `Invoke` is in Build (ADR-0022, Consequences), and more so: its tools
  are not hermetic by design. One allowlisted tool with an undeclared channel collapses the envelope.
- **A rename reaches every decoder.** ADR-0018's decoder targets the floor's alphabet, so each Run Persona's decoder
  changes with this record (G5 item 17).
- **A finished principal holds its lease until it lapses** (§4). The TTL is the only knob.
- **One author.** The custodian settled six choices in discussion; the rest are the drafter's.

## Findings

1. **The schema anticipated the read.** `RunCtx.corpusRoot` has been in the draft schema since 2026.09.24 and no Run
   policy reads it. It becomes the Run root.
2. **ADR-0022's Context sentence was never true.** "Run has such an alphabet" is recovered text and is not amended by
   this record; ADR-0030 §10 finding 4 already says what it got wrong.
3. **Neither outside vocabulary pins a tool's digest.** OpenShell's MCP rules and the Praxis gateway's broker catalog
   (`praxis-proxy/ai`, alpha, as read on 2026.09.29; not a corpus source) both name tools by string. ADR-0022 §3's
   name-plus-digest entry is stricter, and §3 keeps it.
4. **The allowlist entry is where the vocabulary grew.** A three-variant alphabet moves Run's variety into what an
   entry declares. That declaration has no schema yet (Open obligations).
