## Context

ADR-0022 §6 states the confinement obligation and discharges nothing: no shell, no network egress, no filesystem
outside workspace and corpus root, no path to the artifactory except `Submit`. Until a mechanism enforces it, Build
principals are `Mediated`, and ToO assumption of use A1 fails for every deployment. The reference makes the gap
concrete. An agent process with a shell never has to use the MCP front door (ADR-0033 §6).

ADR-0031 §3 gave the evidence somewhere to live, as the lease's `confinement: [digest, rung]` field, and left the
rungs undefined. That is G3 item 19.

The 09.17 session split the gap into two problems. **The mechanism** is commodity in 2026: bubblewrap and seccomp,
gVisor, Firecracker and Kata, confidential VMs. **The instant** is the moment `Contain` knows it is running inside
the mechanism it assumed. The instant is the hard part, and ADR-0031 answered where it sits: at lease grant. What
remains is what each rung means, which rung is the archetype, and how appraisal fits the consistency posture.

**Two tests decide the archetype rung.** Both are already in the corpus.

- **Consensus for grants, local for denials** (ToO 09.10 §2). The core is PC/EC: under partition, a grant waits
  rather than risk split authority.
- **Delegate by failure direction** (*TOPAK vs container orchestration*; ADR-0032 §2 on the temporal axis). The
  substrate may carry a mechanism whose failure only subtracts authority. A mechanism whose failure could add or
  preserve authority is authored by TOPAK and consensus-backed.

Apply the second test to the host. At rung 1 a faulty or hostile launcher produces a valid-looking lease for a guest
it did not confine, which is a failure that adds authority. At rung 2 the hypervisor can alter a running guest after
its launch measurement, which is the same failure one layer down. Only at rung 3 is every residual host power
subtractive. §5 lists them, and §7 checks it.

## Decision

### 1. The confinement profile is a promoted Build artifact

A **confinement profile** is a named artifact whose digest is the first element of the lease's `confinement` field
(ADR-0031 §1). It is produced in Build and promoted under ADR-0024 like a bundle. **A digest nobody promoted is not
a reference value**, so it cannot be attested.

A profile at the archetype fixes seven things:

| # | Clause | What it removes |
|---|---|---|
| **P1** | **One channel.** The guest's only I/O device is a single host–guest channel, such as vsock, to the mechanism's front door (ADR-0033 §2). There is no network device | Egress. The protocol and the channel become the same thing |
| **P2** | **Filesystem.** A measured read-only root, the round's workspace read-write, and the pinned corpus root read-only and content-addressed. Nothing else is mounted | Reads and writes outside workspace and corpus |
| **P3** | **No launcher for the principal.** The only code the principal can cause to run is its own inference and `Invoke` of an allowlisted tool. The image has no shell, package manager or interpreter reachable from the principal | Effects that no action names |
| **P4** | **Tools are Wasm components**, instantiated per call and handed only a workspace directory capability. No sockets, no wall clock, and no entropy source not derived from the inputs | ADR-0022 §3's hermeticity obligation, discharged by construction rather than by review (finding 2) |
| **P5** | **Inference is inside.** The Persona's weights are in the guest, and their digest is part of the launch measurement (ADR-0016 §6). An accelerator, if used, runs in confidential-compute mode, and its attestation is part of the evidence | Prompt egress (ADR-0017) and device-memory paths |
| **P6** | **One principal per guest, one guest per round.** A guest is launched for the grant and destroyed when the round ends. Nothing survives except through `Submit` and `Emit` | Cross-round and cross-principal state (ADR-0008 placement) |
| **P7** | **The profile carries its reference values.** These are the launch measurement it expects and the minimum platform TCB version it accepts. Changing either is a new profile, and so a promotion | Reference values that move without review |

**Build and Run share the schema, not the profile.** The Build profile is fully determined by ADR-0022's alphabet,
and this record discharges §6 for it. The Run profile depends on Run's effect channels, and no record defines Run's
alphabet (G3 item 13). Run is carried as a debt. Until it is paid, Run principals are `Mediated` at every rung.

*Pending ⟨A2⟩, not applied. **The Run profile.** The debt above is paid as follows; on ratification this block
replaces the paragraph's last three sentences, from "The Run profile depends" to "at every rung", the first of which
ADR-0040 already made stale.*

*A Run profile is the same schema with `domain: run`, promoted under ADR-0024 as a Build profile is, and appraised at
the same rungs by the same evidence (§2, §3). Six clauses carry over with the reading Run's alphabet (ADR-0040 §1)
gives them; **P4 is replaced by channel fidelity**, because a Run tool exists to open the socket P4 forbids (ADR-0042
§6). A Run tool runs on the mechanism's side of the front door, reached by the mechanism and never by the guest
(ADR-0033 §2), so P4 is a clause about the tool host, as Build's P4 is a clause about tools.*

| # | Run clause | What it removes |
|---|---|---|
| **P1** | *One channel, to the front door; no network device. Unchanged* | *Egress from the guest. A Run principal's only route to an effect is an `Actuate` admitted at the front door* |
| **P2** | *A measured read-only root and nothing else mounted. Run has no workspace (it has no `Draft`) and the Run root is not mounted: an admitted `Consult` delivers its object over the channel, node-side, as ADR-0036 §3 does `Read` (drafter's choice)* | *Reads outside the Run root, and a second, unrecorded ingress path* |
| **P3** | *No launcher for the principal. The only code the principal can cause to run is its own inference and `Actuate` of an allowlisted tool* | *Effects that no action names* |
| **P4** | ***Channel fidelity.** Every Run tool is a Wasm component, instantiated per call by the tool host, handed a working-directory capability for the round and **one network capability: a connection to the target its allowlist entry declares** (ADR-0040 §3), and no other socket. It may read a clock and draw entropy: a Run tool is not hermetic and is not asked to be. The capability binds the target; the declared `kind` (the protocol) is recorded with the call (ADR-0042 §3) and is not enforced by it* | *An effect on a channel nobody declared. Fidelity holds by construction, a check and not a trust, as P4 makes hermeticity one in Build* |
| **P5** | *Inference is inside. Unchanged* | *Prompt egress and device-memory paths* |
| **P6** | *One principal per guest, one guest per round, and the guest is destroyed when the round ends, which in Run is when the lease ends (ADR-0042 §5). Nothing survives except through `Actuate` and `Report`* | *Cross-round and cross-principal state* |
| **P7** | *Unchanged. The tool host is not in the guest's measurement: its identity is fixed by the release (ADR-0045 T-0045-25)* | *Reference values that move without review* |

*A Run seat without `Actuate` in its alphabet, an Observer's (ADR-0043 §2), meets P4 vacuously, as a Build seat
without `Invoke` does. **Channel fidelity is about which channel, not what is said on it**: an `Actuate` that drives
the declared valve the wrong way is an admitted effect with a record (ADR-0042 §3), for the floor, the bundle and the
Observer, and not a confinement failure.*

*Who checks it: **the tool host's Wasm runtime**, by construction. ADR-0045 T-0045-24, today excluded because "the
declaration is an operator's assertion", becomes **delegated** to T-0045-25 at the archetype, with the residual that
the target is an address and the protocol on it is unchecked; a native Run tool is §8's D-0034-5 or D-0034-6. That
change of class is an amendment to ADR-0045, owed on this amendment's ratification.*

*A2's ratification condition: (i) ADR-0042 §6 is ratified with it, since this discharges what §6 states; (ii) a TLC
check, as a new module, of a tool that may open a channel: an invariant that every effect admitted under a `Contained`
Run lease went through its tool's declared target, broken by a mutation `M_CHANNEL` (a tool opens an undeclared
target) and by `M_NATIVE` (a native tool with no filter), and holding under D-0034-5's filter; (iii) the reference,
with an ADR-0033 addendum: Run profiles registered, a Run tool run as a component with one scoped connection, a call
that tries another target refused by the runtime and seen to fail, and `Contained` reading P4 as channel fidelity for
a Run seat.* *(ii) is `spec/RunConfinement.tla`, run 2026.10.02 (`spec/RunConfinement-results-2026.10.02.txt`):
both invariants hold as specified and under D-0034-5's filter; `M_CHANNEL` and `M_NATIVE` break them as stated; a third
mutation, `M_FILTER`, shows the filter is load-bearing only where D-0034-5 is declared; five witnesses are violated.
Both invariants are also proved, each under the mutations that break it (`spec/RunConfinement_proof.tla`, 116
obligations, `spec/RunConfinement-proof-results-2026.10.02.txt`).
(iii) is built in the reference, uncommitted and without its addendum (`mechanism/` I43, I44).*

**This record does not relax the alphabet.** ADR-0022 still has no shell. The critical review's alternative, a
hermetic shell whose only reachable effects are workspace writes and so is observationally `Draft`, becomes
*possible* under P1–P4 and is left to its own record (Options).

### 2. The rungs, defined

This fills ADR-0031 §3's table and adds no field. **On this axis the numbers ascend with strength**, as ADR-0031
fixed them. The archetype is the top value, not rung 1 as on ADR-0017's axis.

| Rung | Evidence | Appraised by | Trusted for integrity of the guest | An untrusted host can |
|---|---|---|---|---|
| **3** · archetype | Confidential-VM hardware report (the SEV-SNP or TDX class), with the launch measurement covering firmware, kernel, initrd, root hash, profile digest and Persona digest | An **independent verifier**: not the host operator, not the mechanism (RFC 9334 roles) | The CPU vendor's root of trust and firmware, the verifier, and the promoted image | Only subtract (§5) |
| 2 | Measured-boot TPM quote over the same values | The mechanism, against the profile's reference values | Also the host firmware and hypervisor | Launch a rogue image (detected: *Contested*). The hypervisor is trusted not to alter a running guest |
| 1 | The launcher's assertion of the profile it launched | Nobody. The orchestrator is the attester by construction | Also the host operator and orchestrator | Nothing, by assumption. The assumption is the trusted-base entry |
| 0 | None | — | — | `Mediated`, always (ADR-0031 §3) |

**The verifier is a trust root.** It decides what counts as Attested, so replacing it adds authority. Its appraisal
key is carried where the other authority-defining keys are, in the issued rules. Replacing a verifier is an issuance.
ADR-0025 §1 lists what rules contain and has no item for it. This record asks for one and carries the debt.

**Rung 1 cannot produce *Contested*.** With no measurement there is no divergence to detect, which the property
check confirms (§7, `NeverContested` holds at rung 1). Sokolov's verdict lattice exists only from rung 2.

### 3. Appraisal is part of the grant

The grant is already a consensus decision at a fresh fence (ADR-0031 §2). Appraisal becomes one of its conditions.
It is not a separate protocol.

1. **The nonce comes from the log.** It is a hash of the epoch, the committed log index at the request, the
   principal and the round. The guest generates a session key pair, and the evidence binds the nonce and the public
   key. Freshness comes from log position, not a clock (ADR-0032 §3).
2. **One replica appraises; the verdict is ordered.** The proposing replica obtains the evidence and the verifier's
   signed result, and proposes a grant entry. The entry carries the profile digest, rung, verdict, nonce, evidence
   digest and session public key. Replicas do not appraise again, because independent appraisals can disagree and
   ADR-0033 findings 3 and 7 already show what replicas disagreeing about liveness costs. At apply, each replica
   checks the verifier's signature and that the nonce's epoch is still current. That is the apply-time re-check of
   ADR-0033 §4 with one more condition.
3. **Three verdicts:**

   | Verdict | Meaning | Mechanism response |
   |---|---|---|
   | **Attested** | Signature valid, measurements match the profile | Grant at the deployment's declared rung |
   | **Unattestable** | No evidence, stale nonce, expired endorsement, or verifier unreachable | **Refuse.** No grant, and not a grant at a lower rung |
   | **Contested** | Signature valid, measurements diverge (Sokolov, arXiv:2608.00801) | Refuse, and order a **targeted revocation of the principal** (ADR-0031 §5), attributed under F2 with the evidence |

4. **No silent downgrade.** A principal whose evidence does not reach the declared rung is refused, not granted as
   `Mediated`. Downgrading would turn a declared vacuity back into a silent one, and a silent vacuity is the failure
   this record exists to fix. **The same holds at renewal** ⟨R1⟩: a renewal keeps the rung (ADR-0031 A1), so a live
   lease is always at the declared rung, and a principal whose evidence stops reaching it loses its lease rather
   than its containment.
5. **The session is the attested guest's.** Every action after the grant is authenticated by the attested session
   key, so a lease cannot be used from any other guest, including the same principal's next one. At rungs 2 and 3
   this replaces the reference's bearer token for principals (`mechanism/` I14, G5). At rung 1 the launcher binds
   the session and is trusted to.
6. **Re-attestation is triggered by events, not intervals.** It happens at every renewal with a fresh nonce
   (ADR-0016 §6), and a failed renewal lets the lease expire, which is a local subtraction. It is never a renewal at
   a lower rung (§3.4) ⟨R1⟩. An Attested re-appraisal renews at the same rung, an Unattestable one lets the lease
   lapse, and a Contested one is a targeted revocation, as at grant. **Re-attestation measures the launch again,
   not the running guest** (finding 5), so what it adds is freshness against the log and the current verifier and
   reference values, not integrity of the instance. An epoch fence invalidates every pending appraisal. No re-attestation interval exists, so ADR-0032 §2's trusted-time
   requirement for one does not arise. The longest unattested span is one lease TTL, inside a guest that lives for
   one round.
7. **A Contested revocation targets the principal**, not the profile or the Persona digest. The divergence belongs
   to one instance. Revoking the profile would let one hostile host deny every principal that uses it. A revocation
   is permanent within the chain (ADR-0031 §5), so a host fault costs a principal identity, and that cost is
   intended.

**This is PC/EC.** If the verifier is unreachable, no grant is made, which chooses consistency over availability in
exactly the place ADR-0031 already put a consensus decision. Live leases are unaffected until renewal. Every
response that subtracts (refusal, expiry, revocation) takes the path that needs no quorum.

### 4. `Contained`, stated

`Contained(p)` holds when all of the following hold:

- `p` holds a live lease at rung ≥ 1, granted on an **Attested** verdict at the deployment's declared rung;
- the lease's profile meets **P3–P5**: no launcher, Wasm tools only, inference inside; *for a Run principal, P4 is channel
  fidelity (§1, the Run profile)* ⟨A2⟩;
- the Persona is **in house** on ADR-0017's axis, at the archetype or its rung 1, so the weights are possessed and
  no prompt leaves the guest;
- **ADR-0017's lineage-independence criterion is in force** ⟨R2⟩: ADR-0035 is ratified and its θ values are set as
  floor values.

**The provenance axis must clear, as ADR-0031 §3 says** ⟨R2⟩. ADR-0031 reads it two ways at once: §3 names prompt
egress, which the third conjunct covers, and its open obligations say `Contained` stays unreachable without the
criterion "however well attested the substrate is". This record takes both, and the reference already does
(`PROVENANCE_CRITERION_DEFINED`). The fourth conjunct is a fact about the deployment's rules, not about `p`: until it
holds, **`Contained` has no members at any rung**, and ToO rev 7 §2.3's "unreachable at every rung today" stays
accurate. What this record changes is the reason. Before it, no rung had semantics. After it, the criterion is the
only missing premise (finding 1). ADR-0017's table is unchanged: its rung 1 is `Contained`, with a lineage debt,
once the criterion is in force.

*The draft read otherwise* ⟨R2⟩. It made independence not a conjunct, on the ground that the criterion concerns
monoculture and the Observer rather than effect exclusivity. That argument is recorded in Options and was not
taken.

**Rung 0 is `Mediated`, always**, and `Lease.tla`'s `Rung0NeverContained` is unchanged.

### 5. What an untrusted host can still do

| Host power | At rung 3 | Direction |
|---|---|---|
| Refuse to launch, kill, pause, starve CPU or memory | Round ends, or its lease expires | Subtracts (availability) |
| Withhold or delay the channel | Actions do not arrive | Subtracts |
| Launch an image other than the one asked for | Measurement diverges: *Contested*, principal revoked | Subtracts |
| Alter a running guest | The hardware's integrity protection makes this the guest's death | Subtracts, **assumed** (§6) |
| Attach a device, such as a network card | Changes the measurement at the next attestation; P1's image brings up no other device | Subtracts |
| Side channels, physical memory interposers | Not prevented | **Residual** (§6) |

Every row except the last only subtracts. That is the delegation test from Context, met by construction rather than
by trusting the host.

### 6. The trusted base, per rung

| Rung | Enters the trusted base | Leaves it, compared with rung 1 |
|---|---|---|
| 3 | CPU vendor root of trust and firmware; the independent verifier; the promoted image, including the Wasm runtime | Host operator, orchestrator, hypervisor and host kernel, for guest integrity. They keep availability |
| 2 | Also host firmware and hypervisor | Host operator, for launch integrity only |
| 1 | Also host operator and orchestrator | — |

**This trades an assumption for a mechanism.** A1 was an assumption with nothing behind it. At rung 3 it becomes a
claim resting on named, audited components. ADR-0029's non-increasing-TCB rule is not breached by the trade, but it
must be recorded in the TCB declaration record, which does not exist yet (G3 item 16). That is carried as a debt.

**The hardware sits in the "operationally audited" layer** (Moon & Varshney, Figure 1). The containment theorem at
rung 3 is conditional on audit evidence about the CPU vendor's isolation, not on proof. Published physical-access and
side-channel attacks against confidential-VM platforms are the residual, and the record says so on its face. That is
still strictly more than A1 conditioned on nothing.

**The criterion conjunct is not modeled** ⟨R2⟩. It is one deployment-wide fact, taken as holding. With it false,
`Contained` is empty and `NeverContainedEffect` holds trivially, so the ratification witness below is conditional

**Two clauses are about honest declaration, not containment.** Under `M_STALE`, `M_DOWNGRADE` and `M_RENEWLOW`

rung 3 and is running principals below it. `FreshAppraisal` guards what the model leaves out: a fence ordered because
a verifier or a reference value is suspect. Both are kept, and neither is presented as a containment property.

**Ratification condition.** `Safe` holds at every rung, and `NeverContainedEffect` is violated at rung 3. Rerun
if the profile schema, the verdict set or the rung table changes. **ADR-0031 A1 is ratified with this record or
before it** ⟨R1⟩: without it, §3.4 holds at grant and is bypassed at renewal.

## Consequences

**Positive**
- **`Contained` has a way to get members.** For the first time the corpus can name a deployment, rung 3 with an
  in-house Persona, in which ToO A1 holds as a mechanism claim, once ADR-0035 is in force ⟨R2⟩.
- **The rung ladder is checked, not asserted.** One mutation shows exactly what each rung's trusted-base entry is
  load-bearing for.
- **`Invoke` hermeticity has an owner** for Wasm tools. ToO A2 is discharged by construction for them.
- **Vacuity is declared.** A deployment's rung is in every lease, and a principal below it is refused, not quietly
  demoted.
- **The instant costs nothing new.** Appraisal rides the grant that ADR-0031 already made the instant, and its
  freshness rides the log.
- **Principals get real authentication** at rungs 2 and 3, from the attested session key.

**Negative**
- **Almost nobody can afford the archetype.** It needs confidential VMs, confidential-compute accelerators, an
  in-house Persona and an independent verifier. As with ADR-0017, the record labels it a target and specifies the
  rungs below it as carefully.
- **One guest per round** adds launch and attestation latency to every grant. Build (PC/EC) can afford it. Run's
  budget has not been measured.
- **The verifier is on the grant path.** Its outage stops grants, by design.
- **A host fault costs a principal identity** (§3.7).
- **The hardware is audited, not proved**, and has a published attack history (§6).
- **The capability cost is unchanged.** Still no shell, no package manager, no git.
- **Run is not discharged.**
- **`Contained` stays empty until ADR-0035 is in force** ⟨R2⟩, and ADR-0035 waits on θ values measured from real
  corpora. The confinement half can be built and checked first; the membership claim cannot be made until then.

## Findings

1. **An observation whose reason this record changes** ⟨R2⟩. ToO rev 7 §2.3, ADR-0031's open obligations and G3
   item 20 observe that `Contained` is unreachable at every rung today. It stays true until ADR-0035 is in force
   (§4). Before this record the reason was that no rung had semantics; after it, the criterion is the only missing
   premise. No decision text changes. ToO rev 8 and the next checkpoint's open list should narrate the new reason,
   and ADR-0031's obligations list strikes rungs 1–3 as discharged, as it struck the clock model for ADR-0032. *As
   first drafted, this finding said the observation became stale; R2 withdrew that.*
2. **ADR-0022 §3's hermeticity obligation splits.** For Wasm tools it is discharged here by construction (P4). For
   native tools it stays unowned, and using one is D-0034-3.
3. **ToO A1's wording names a mechanism without naming who attests it.** At rung ≥ 1 it becomes "enforced by a
   declared, attested profile". A1 should cite this record's rung.
4. **The reference's bearer token (`mechanism/` I14) has a replacement** at rungs 2 and 3. G5 narrows to operators
   and replicas.
5. **Re-attestation at renewal cannot detect a running guest being altered** ⟨R1⟩. Rungs 2 and 3 measure the
   launch, and a renewal re-measures the same instance (§3.5, P6), so `NeverRenewContested` holds at every rung.
   What renewal can newly return is Unattestable: a verifier outage, an expired endorsement, or a reference value
   or platform TCB version withdrawn since the grant. Integrity of the running guest rests on §5's hardware row
   at rung 3 and on the trusted base at rungs 1 and 2, never on re-attestation. This makes the platform-TCB
   obligation below the main thing renewal is for.
6. **The module reads a launch measurement at rung 0** ⟨A1⟩. Under `M_HOST` at `Declared = 0` the module reaches
   *Contested* (`hx0` in the 2026.09.30 results, 159 states), which §2 says rung 0 cannot produce: `Evidence(p)` reads
   the launch measurement for every rung but 1, and rung 0 has no measurement either. The one-line correction is
   `Evidence(p) == IF Declared <= 1 THEN guest[p].asked ELSE guest[p].boot`. It moves the digest this record cites,
   so it belongs in a successor module, as `Lease_A1.tla` was to `Lease.tla`, when the rung-2 record next touches
   this module. Nothing checked at rungs 1–3 depends on it.
