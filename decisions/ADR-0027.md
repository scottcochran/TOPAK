# ADR-0027 — Genesis rules are resident

**Status:** Accepted (genesis) · 2026.09.23 ⟨B2⟩
**Status note:** Confirmation required: no. Bootstrap set — ADR-0029 §4's exception, since the
confirmation promotion runs under this record.
**Split from:** ADR-0025 revision 2, by decomposition
**Depends on:** ADR-0025 (anchor), ADR-0026 (rules floor)
**Precedent:** ADR-0012 (resident policy floor)

---

## Context

The anchor issues rules. At cold start, and under partition, the anchor may be unreachable. If
genesis rules were fetched, the promotion roster and the break-glass roster would have no
definition until the anchor answered. Every grant path would block. The deny path would too, if any
deny consulted a roster.

ADR-0012 was ratified ahead of its parent on exactly this availability argument for the policy
floor. The same argument applies to rules.

**Why this is a separate record.** A future decision to bootstrap genesis rules from, say, a
hardware root at boot would supersede this clause alone. ADR-0025 and ADR-0026 would stand.

## Decision

1. **Genesis rules are pre-blessed and resident.** They ship with the mechanism release and are
   fetched from nowhere.
2. **Genesis rules must satisfy the rules floor** (ADR-0026). At epoch 0 this is discharged by
   `GenesisSatisfiesFloor` in the `Genesis` bootstrap module (ADR-0029 §5), not by a promotion:
   the genesis bundle is the only artifact never promoted (ADR-0029 §5, ceremony step 4), and at
   epoch 0 there is no roster to promote under except the one the genesis rules themselves define.
   A **later** mechanism release carrying resident rules is checked at its promotion. ⟨R1⟩
3. **Anchor unavailability blocks change, never operation.** The system runs on the last resident
   rules at the current rules epoch. **An admitted issuance is persisted with the same residency as
   genesis rules** ⟨R1⟩; without that, "the last resident rules" would name nothing after epoch 0,
   since §1 makes only the genesis set resident.
4. **Genesis is the root of the rules epoch chain.** Epoch 0 is the genesis rules. Re-genesis (A-0025)
   starts a new chain, not a continuation.

## Consequences

**Positive**
- **Fail-closed operation needs no anchor.** This is the authority analogue of ADR-0012.
- **Resident rules are safe.** Stale rules are safe in the same sense stale bundles are: bounded by
  a verified floor.

**Negative**
- **Rotation cannot outrun release cadence.** Genesis contents change only with a mechanism release.
- **A compromised genesis is a compromised system.** No later issuance can prove the genesis was
  honest; genesis is covered by ADR-0025's intent axiom.

## Open obligations

- **Genesis contents and key ceremony** (carried from ADR-0025).
