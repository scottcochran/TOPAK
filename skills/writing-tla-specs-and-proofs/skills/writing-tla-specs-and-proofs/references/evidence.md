# Evidence: results files, digests, freezing, and what stays trusted

A TLA+ development's claims are only as good as the files that record them
and the care with which the words "checked" and "proved" are used. This
reference is the bookkeeping that keeps a corpus of modules, runs and
proofs honest over months of change.

## The results file is the evidence

Every claim a design record makes about a module points at one file:

| Claim | File | Generated by |
|-------|------|--------------|
| each mutation fails its property, each witness is reached, `Safe` holds, at small constants | `<Module>-results-<date>.txt` | the run script or the row-list generator |
| the same at practical constants | `<Module>-results-<date>-medium.txt` | the same, with the row that did not finish recorded with its time allowed |
| no error sampled at large constants | `<Module>-simulate-results-<date>.txt` | the simulation script, with depth, traces and seed |
| every invariant proved under named hypotheses | `<Module>-proof-results-<date>.txt` | the proof results generator |
| the same with every SMT and Zenon obligation checked by an independent checker | `<Module>-proof-cert-results-<date>.txt` | the certification driver |
| every proof in step with the tree | the sync script's output, run before a cut | the sync script |

Properties of every such file:

- **Dated.** The name carries the date; a rerun that changes anything is a
  new file beside the old one. The old file stays, cited by whatever cited
  it.
- **Header first.** What is checked, by which tool at which version and
  digest, over which module at which digest, under which constants; and an
  expected line stating in prose what every row should read.
- **Generated, never edited.** The generator compares each row to its
  expectation and exits non-zero on a mismatch or on zero rows. A
  regeneration must reproduce the cited file byte for byte, and where it
  cannot (a prover that reuses results between identical obligations and
  so changes its evidence digest), the file says what a rerun does
  reproduce.
- **Committed with what it measures.** Module, run script or row list,
  results file and the README row in one commit.

## Digests and pins

- **The model checker jar is tracked**, for its digest, behind a wrapper
  script; the digest appears in every results file.
- **The prover is installed, not tracked** (it is large), and **pinned**: a
  pin file names the version, the commit, the binary's digest and the
  backends. The wrapper refuses a binary whose digest does not match unless
  an explicit override variable is set, so a results file from another
  build is produced knowingly. The installer compares what it fetched with
  the pin; a pre-release tag that upstream rebuilt under the same name is
  recorded as observed, not pinned.
- **A proof results file prints the digest of every module in the `EXTENDS`
  chain**, in dependency order, on one `Modules:` line, and the prover's
  digest on a `Prover:` line. That line is the only record of which
  specification a proof is a proof of.
- **The checker's own identity**, in a certified run: the solver, the proof
  checker, its signature and the wrapper, each by digest, in the header.
- **Where the binary cannot be measured by a manifest, the pin file is.** A
  checkpoint manifest over the tree measures the pin, so the identity of
  the prover behind every proved obligation is in the corpus even though
  the binary is not.

## Freezing and successor modules

**A module cited by digest in an accepted record is frozen.** A change is a
successor module beside it: `Lease_A1.tla` beside `Lease.tla`,
`RulesFloorNV_rev5.tla` beside `RulesFloorNV.tla`. The frozen pair stays as
it was, cited by the records that cite it.

When a specification changes:

1. Write the successor module, as the design records require.
2. Copy the proof module to `<Successor>_proof.tla`, point its `EXTENDS` at
   the successor, re-prove. A changed guard shows up as a failed obligation
   at the action; a changed property as a failed `Init` or `Next` step; a
   changed mutation as a hypothesis that no longer discharges. Each is the
   prover saying what moved.
3. Generate the successor's TLC results and proof results, and commit the
   successor module, its TLC results, the successor proof and its results
   together.
4. The record that cites the successor by digest cites its proof the same
   way.

When a proof changes and the specification does not: re-prove, regenerate,
commit both. The results file's date moves and the base digests do not. A
weaker hypothesis is a stronger theorem and is worth a results file of its
own.

**Why proofs are not merged into modules.** Three reasons, each
sufficient: a base module is frozen by digest, and adding a proof would
make it a successor of itself; TLC runs the base module without the
prover's library, and a merged module would carry `EXTENDS TLAPS` into
every run; and the proof carries hypotheses (`Mut # "M_X"`) that the module
must not, since the module exists so TLC can flip each mutation. The cost
is one line per module in the sync script and one digest line per results
file.

**A liveness module follows the same rule**: it extends the frozen safety
module, changes `Next` only under its own mutations, and its proof module
proves `SpecL => Spec` so the safety theorems carry over.

## The sync script

For every `<M>_proof.tla`, take the newest `<M>-proof-results-*.txt`, read
its `Modules:` line, compare each digest with the tree, and print one row:
`IN SYNC` or `STALE: <module that moved>`. Then check every results file's
`Prover:` digest against the pin. Then list every base module with no
proof and the reason recorded for it, and **fail on a base module with no
reason**. Exit non-zero on any stale proof, missing results file, unpinned
prover, or unexplained gap. With a `--run` flag, re-check each stale proof
with the prover, so the output says whether the drift broke the proof or
only the digest (no results file is written; that is a separate,
deliberate step).

Recorded reasons look like: "shared definitions, no `Spec`; its one fact is
proved as a lemma in two proof modules"; "frozen and superseded by
`<Successor>`, which is proved"; "a trace replay, not a transition system
with invariants; its target is the refinement".

## The vocabulary of claims

| Word | Means | Bounded by |
|------|-------|------------|
| **checked** | TLC found no violation over every reachable state of the model at these constants, and found each mutation's and witness's violation | the constants; the checker |
| **proved** | the prover discharged `Spec => []P` under the module's named assumptions and the theorem's hypotheses | the hypotheses; the prover and its backends |
| **certified** | proved, and every SMT and Zenon obligation's proof was accepted by an independent checker | the prover's translation and normalization; the temporal backend; the checker |
| **sampled** | TLC in simulation mode found no violation in N random behaviours to depth D | the sample; never cited as a check |
| **holds** (of a deployment) | every trusted-base row the property rests on is declared, every parameter premise holds, no declared gap is open | the premise table |

A proof is bounded by its assumptions and its prover where a TLC row is
bounded by its constants. **Neither is a claim about running code** until a
refinement from the code to the module exists, and the records should say
so in a standing sentence rather than in each place the gap could be
misread.

Keep a **premise table**: one row per property, naming the trusted-base
rows it rests on (the checker, the prover, the engine whose semantics a
guard assumes), the parameter premises (the values whose degeneracy voids
it), the declared gaps, and the "Breaks under" column that the proof's
hypotheses restate. Writing the proofs corrected that column several times;
the table is what makes the correction a recorded fact rather than a
remembered one.

## What each tool leaves trusted

| Tool | What its answer rests on |
|------|--------------------------|
| TLC | the jar at its digest; the constants run; the module text at its digest |
| tlapm, uncertified | the prover's front end (parsing, expansion of definitions, `ENABLED` and primes, normalization, which closes about two obligations in three with no backend); each backend's soundness (SMT, Zenon, Isabelle, LS4 for temporal steps) |
| tlapm, certified | the front end still; Isabelle; LS4 for the one to three temporal steps per theorem, which no checker confirms; the proof checker, its signature and the wrapper, in the SMT solver's place |
| a second prover (Lean) | its kernel and toolchain at the pin; the encoding's fidelity to the module text, which is read or, where possible, checked against TLC's state graph |

Name the prover a **trusted-base row** in the records, beside the checker,
with its identity fixed by the digest every results file prints, and with
its residual stated: what is unexamined (each backend's soundness), what
is known (the translation's two unsound cases, see
[prover-habits.md](prover-habits.md)), and what it is not a claim about
(what runs).

## Certification: checking the checker

An ordinary run hands each obligation to the backends in turn and takes
the first answer. A certified run takes nobody's word that can be checked:

- the SMT backend is a **wrapper** that runs a proof-producing solver,
  replaces the declarations the proof restates with the query's own,
  requires every assumption of the proof to be one of the query's
  assertions, and forwards `unsat` only when an independent checker
  accepts a proof of false;
- Zenon's scripts are checked by Isabelle (`-C`), which checks exactly
  those and nothing else: a module whose obligations all went to SMT
  gives Isabelle an empty theory and "No errors found" is vacuous;
- a driver runs the module so and prints a results file that accounts for
  every obligation by the route that discharged it: trivial, SMT checked,
  Zenon checked, Isabelle, LS4;
- a **self-test** shows the wrapper refusing a solver that proves another
  query, proves nothing, or drops a step. A gate that cannot fail proves
  nothing.

A module is certified when every obligation is trivial, has a checked
proof, or is a temporal step. Most certify unchanged; those that do not
are recorded as uncertified with the obligation named, and their proofs
restructured in successor modules. A refused reconstruction is a missing
check, not a counterexample.

## A second route

The temporal step each theorem ends with, "holds initially, every step
keeps it, so always", is the one route no checker confirms. A second
derivation in a kernel-checked prover (Lean 4, without Mathlib) does that
step as an induction on reachable states, with the same inductive
invariants and the same hypotheses on `Mut`, at the price of a new
premise: that the encoding is the module. Where that premise can be
checked rather than read (TLC dumps the module's state graph; a mirror of
the encoding, proved equal to it, is evaluated on every state and edge),
do so, because an encoding laxer than the module can prove an `ENABLED`
theorem the module does not satisfy. End every such results file with a
kernel replay of the whole package in a fresh environment: a declaration
added past the kernel reports no axioms, and only the replay refuses it.

The second route does not certify the first; it proves the same theorems
again under different premises, so that a result is voided only when both
routes are lost.

## The order a property passes through

1. **Write the specification so its properties are local.**
2. **Model-check at small constants**: every mutation fails, every witness
   is violated, `Safe` holds. Dated, digest-stamped, regenerated.
3. **Model-check at practical constants**, into a `-medium` file; record a
   row that does not finish.
4. **Simulate at large bounds, as time allows**; "no error sampled", never
   a check.
5. **Validate the implementation's traces** through an operational model
   of its state machine, step for step: drift detection, not refinement.
6. **Prove the invariants**, each under the mutations that break it and the
   module's named assumptions; a proof replaces no mutation row.
7. **Keep the proofs in step**: the sync script before every cut; a
   successor module gets its proof in the same commit.
8. **Regenerate, never hand-edit.**
