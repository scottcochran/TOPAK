# Writing TLA+ Specs and Proofs

A method for TLA+ developments in which the specification, the model
checker and the prover each do one job and the evidence for each job is a
file that can be regenerated. It is distilled from a design corpus whose
twenty-four proof modules, over three thousand obligations, were written in
a few working days, because the specifications had been written first for
mutation testing and that style made nearly every invariant inductive.

**Core principle: write the specification so that its properties are
local, then let each tool answer the question it is good at.** TLC answers
existential questions at small constants: this mutation reaches a bad
state, this witness is reachable, this fair spec has a behaviour. TLAPS
answers universal ones: this invariant holds of every behaviour, for every
constant the module's assumptions admit. Neither is a claim about running
code. The results file, dated, digest-stamped and regenerated by a script,
is the only form the evidence takes.

## When to Use

- Writing a new TLA+ module for a mechanism, protocol or policy
- Adding a mutation (a guard the mechanism must have) or a reachability
  witness (a state the mechanism must be able to reach) to a module
- Writing or repairing a TLC run script, a row list or a results file
- Writing a TLAPS proof module for the invariants a module states
- Finding the inductive strengthening of an invariant that is not
  inductive as stated
- Diagnosing a failed obligation, a Zenon or Isabelle refusal, or a step the
  SMT backend cannot close
- Adding fairness and leads-to properties to a safety module
- Changing a module that evidence already cites, as a successor module
- Reviewing a TLA+ development: what is checked, what is proved, under
  which hypotheses, and what stays trusted

## When NOT to Use

- PlusCal translation and algorithm-level modelling as the main activity;
  the method here is for hand-written transition systems whose properties
  will be proved, and a translated module's actions are rarely shallow
- Apalache, symbolic or type-annotated checking: the run-script and
  results-file conventions carry over, the inductive-invariant workflow
  does not depend on the checker, but the tool-specific guidance does not
  apply
- Refinement mappings between a large and a small module: nothing here is
  wrong for them, but the cheap proofs this method produces come from
  modules without `INSTANCE` and without refinement, and a refinement proof
  is a different and harder job
- A project with its own conventions for module layout, naming or results:
  defer to its README and CONTRIBUTING

## The workflow

### 1. Write the specification so its properties are local

The whole method rests on this step. A property is **local** when the
one action that could violate it can be checked against its guard, in one
state, without history. Three devices make nearly every safety property
local:

- **A flag the violating action would set.** `admittedUnlive' =
  (admittedUnlive \/ ~LiveObserver)` inside `Admit`; the property is
  `~admittedUnlive`. The flag is monotone, so the invariant is inductive
  exactly when the condition is false at that action under the hypothesis.
- **An append-only set of records** the property quantifies over.
  `acted' = acted \cup {[seat |-> s, kind |-> KindOf[s], act |-> a]}`; the
  property is `\A x \in acted : x.act \in KindBound(x.kind)`. The inductive
  strengthening is one state fact about what the appending action can
  append, which is its guard's precondition.
- **Every mechanism check as a guard on the action that needs it.** Not as
  a side condition in a property, not as a constraint on `Init`.

Then the shape of the module:

- **One `Mut` constant, one guard per mutation, a `Never…` witness per
  reachability claim.** `Mut = "none"` is the mechanism as specified; each
  `Mut = "M_X"` removes one guard, and the header says which property it
  must break. Each `Never…` operator is a property that must be
  **violated**: `NeverRefused == ~refused` shows that refusal is reachable
  at all. A module without witnesses can hold every property vacuously.
- **A type invariant** (`TypeOK`), as functions from the principal set to
  record sets, with the empty record (`NoLease`) a proved member. The prover
  needs the function's domain in scope to say that `EXCEPT` on one principal
  leaves the others alone.
- **Shallow actions**: a guard, one `EXCEPT`, `UNCHANGED` for the rest. Fold
  `IF Mut = ...` into a constant operator (`ByKind(s)`) so the mutation lives
  in a definition and the actions stay uniform.
- **Finite, literal domains**: two principals, three seats, kinds as string
  literals. The SMT backend settles these by enumeration.
- **Constants unconstrained in the module, bounded in the run script.** A
  bound that only cuts the state space (`MaxRound`, `MaxEpoch`) needs no
  assumption in the proof, which then holds for every value of it. A
  well-formedness condition on the constants themselves (three markers are
  distinct) is different: state it in the module as a **named** `ASSUME`,
  so TLC checks the config against it and the proof cites it by name.
- **A terminating system names its terminal predicate** (`GameOver`), so
  the deadlock check can be turned off for that reason alone and the
  liveness property is its complement, `<>GameOver`.
- **A header that is the contract**: each property with the section of the
  design document it states; each mutation with the property it must break;
  what time, identity or failure is abstracted and how.
- **No liveness unless the design claims it**; then fairness as conditions
  on actions of `Next`, each named for whose obligation it is (see
  [model-checking.md](references/model-checking.md)).

Full rationale and a worked module in
[spec-design.md](references/spec-design.md).

### 2. Model-check at small constants

Every module gets a run script that writes the `.cfg` itself, runs TLC with
`-deadlock` unless a deadlock check is the point, and prints one row:
`name | Mut=… | Property | HOLDS or COUNTEREXAMPLE | N distinct states`.
The results file is the concatenation of rows for

- every property under `Mut = "none"`: `HOLDS`;
- every mutation against the property it must break: `COUNTEREXAMPLE`;
- every mutation against the properties it must **not** break: `HOLDS`
  (this is the "Breaks under" column, and it is what the proof's
  hypotheses will later restate);
- every `Never…` witness under `Mut = "none"`: `COUNTEREXAMPLE`.

The results file is dated, prints the checker's version and digest and the
module's digest, is regenerated by a script from a row list, and is never
edited. TLC's result at small constants is **non-vacuity and
discrimination**, not proof: the vocabulary is **checked**. A `-simulate`
run at large constants is a third kind: "no error sampled", recorded with
depth, trace count and seed, never cited as a check.

Run scripts, row lists, liveness rows and the deadlock flag in
[model-checking.md](references/model-checking.md).

### 3. Prove the invariants, in a module that extends the spec

A proof module `EXTENDS <Module>, TLAPS` and edits nothing in the module it
proves. It states the module's constant assumptions as named `ASSUME`s
(`ASSUME KNat == K \in Nat`), because the prover does not use an unnamed
module-level assumption. Then, in order:

1. `TypeOK`, proved under every mutation as its own `Init` and `Next`
   lemma. Every later lemma cites it.
2. One `Next` lemma per invariant group, hypotheses in its `ASSUME`,
   one step per action: the `UNCHANGED vars` case, each top-level disjunct
   of `Next`, each `\E p \in S : A(p)` as `ASSUME NEW p \in S, A(p)`.
3. The theorem, three lines: the `Next` lemma restated as
   `Inv /\ [Next]_vars => Inv'`, the `Init` lemma, and `PTL DEF Spec`.
   When the inductive invariant strengthens the property, add `Inv => P`.
4. `SafeAlways`, under `Mut = "none"`, citing each theorem in an explicit
   `Spec => []P` step before the `PTL` step. A `Mut` hypothesis cannot be
   discharged inside `PTL`.
5. One lemma per mutation stating what the mutation admits, in the
   module's vocabulary: `MutNoCoupleAllowsAll == ASSUME Mut = "M_NOCOUPLE"
   PROVE Allowed`. The counterexample itself stays with TLC; the lemma says
   why it must exist.

```tla
THEOREM UnreadBoundedAlways ==
    ASSUME Mut # "M_MARK", Mut # "M_ROUNDS", Mut # "M_NOCOUPLE"
    PROVE  Spec => []UnreadBounded
<1>1. InvU /\ [Next]_vars => InvU'
    BY NextInvU
<1> QED
    BY InitInvU, <1>1, InvUBounded, PTL, KNat, RNat, MaxRoundNat DEF Spec, Rounds
```

**Each theorem takes as hypothesis only the mutations that break it.** The
weakest hypothesis costs nothing extra, documents what the property is
sensitive to, and repeatedly corrects the "Breaks under" column: a
mutation the results file never ran against a property turns out to break
it, or a listed one turns out not to. A `Mut` hypothesis is the proof's
way of naming which guard the property rests on.

Check with `tlapm --cleanfp --strict <Module>_proof.tla`. `--cleanfp`
discards fingerprints so nothing is taken from an earlier run; `--strict`
makes a failed obligation a non-zero exit. Only the final count and the
exit status matter; a backend's failure line is noise when another backend
closed the obligation.

Proof structure, the patterns and the prover's habits in
[proof-style.md](references/proof-style.md) and
[prover-habits.md](references/prover-habits.md).

### 4. Check the proof's own non-vacuity, then generate the evidence

- **Flip one hypothesis.** Copy the proof module to scratch, change
  `Mut # "M_X"` to `Mut = "M_X"`, run again. The prover must report failed
  obligations. A proof that survives is proving the wrong thing: the
  hypothesis is not load-bearing, or the invariant is weaker than the
  property. The failing count stays in the session; a mutated proof is not
  an artefact.
- **Generate the results file** with a script that prints the digest of
  every module in the `EXTENDS` chain and of the prover binary, the
  assumptions, the theorems and lemmas by name, and the prover's own
  obligation count, and exits non-zero if any obligation fails.
- **Commit module, results file and the README row together.**
- **Keep proofs in step with a sync script** that reads each results
  file's digest line, compares with the tree, and reports `IN SYNC` or
  `STALE`; it also lists base modules without a proof and the recorded
  reason for each, and fails on a module with no reason.

Results files, digests, pins, freezing, successor modules and what stays
trusted in [evidence.md](references/evidence.md).

## Finding the inductive invariant

Decide the inductive invariant **before** writing the `Next` lemma. Work
up this ladder and stop at the first rung that fits.

0. **Read the guard the mutation removes.** For each invariant, the guard
   its mutation deletes is what the inductive step will rest on. The
   "Breaks under" row of the results file is a list of which guard each
   proof uses.
1. **Flag invariant**: inductive by itself. The proof is that the flag's
   condition is false at the one action that sets it, under the hypothesis,
   against that action's guard. No auxiliary invariant.
2. **A recorded value agrees with the derived truth**: the property is
   over a derived predicate (`ThreeInRow(p)`) and is not inductive because
   a state can break nothing yet lead to a violation. Strengthen to "the
   derived truth is what the recorded variable says" (`ThreeInRow(p) =>
   winner = p`); the property follows because the record holds one value.
   The step case needs a frame lemma: one party's action cannot make the
   predicate true for another (see [proof-style.md](references/proof-style.md)).
3. **Append-only set**: one state fact about what the appending action can
   append (an alphabet, a floor entry, a bound), written as the guard's
   precondition over the state. Prove it with `TypeOK`, under every
   mutation if it holds there, and let each property split on top.
4. **Valid state predicate**: the property is true of every state under
   its hypothesis, by definition, not by induction. Prove it as a state
   lemma and let `PTL` lift it to `[]`. An invariant over `ENABLED`
   (`tLive => ENABLED Consult`) is usually here, proved
   `BY ExpandENABLED DEF Consult`.
5. **Established and frozen**: when every action after a commit point needs
   the commit flag false, prove the property once at the commit action and
   carry it with a lemma that every step either is the commit or leaves the
   committed values alone.
6. **Arithmetic in layers**: ask, action by action, what each needs of the
   state to keep the bound. A grant needs future rounds untouched; a
   heartbeat needs the mark below the sequence; the next grant needs the
   idle seal equal to the sequence and past marks equal to seals. Prove the
   clauses that hold under every mutation (`Shape`) once; the clauses that
   need the mechanism (`Past`, `Bound`) sit on top, each under its own
   hypothesis.
7. **Generation binding**: when the record an action appends depends on
   state set several actions earlier, carry that history forward
   conditionally on "same generation", and make every relaunch strictly
   raise the generation so each clause is preserved. This is the rung where
   the invariant has to be invented rather than read off a guard; budget
   for it.

When the prover fails a step that TLC passed, the usual cause is a missing
clause the checker could not see (only admitted effects are recorded as
having gone a certain way; the asked image is the one that was booted). The
prover finds these; take them as corrections to the specification's
documentation, not as prover weakness.

## Quick reference

| Rule | Why | Enforced by |
|------|-----|-------------|
| State each property as a flag or over an append-only set; checks as guards | makes the invariant inductive at one action | review; a non-inductive `Next` step |
| One `Mut`, one guard per mutation, header names what each must break | TLC can flip exactly one thing; hypotheses name the guard | results rows: every mutation `COUNTEREXAMPLE` on its property |
| A `Never…` witness per reachability claim, each `VIOLATED` | a property that holds of an unreachable state is vacuous | results rows |
| `TypeOK` first, under every mutation, cited everywhere | the backend needs function domains to reason about `EXCEPT` | failed steps about `f'[q]` for `q # p` |
| Weakest hypothesis per theorem (`Mut # "M_X"` only for the mutations that break it) | documents sensitivity; corrects the premise table | flip-one-hypothesis check |
| Mutations and witnesses stay with TLC; the proof carries one lemma per mutation | the prover proves universal statements; a counterexample is a behaviour | results file names the TLC file |
| `SafeAlways` cites each theorem in an explicit `Spec => []P` step before `PTL` | `PTL` cannot discharge a `Mut` hypothesis | the obligation fails otherwise |
| Constants bounded in the run script, not the module; proof assumes only what it needs | a space-cutting bound needs no assumption, so the theorem covers every value | theorem statement |
| Results files dated, digest-stamped, script-generated, never edited | the file is the evidence; a hand edit is the one change it never takes | regeneration byte for byte |
| "Checked" for TLC at constants, "proved" for the prover under named hypotheses, "sampled" for simulation | each word names what bounds the claim | review of every record that uses them |
| A module cited by digest is frozen; change it as a successor module with its own proof in the same commit | evidence cites the digest; the proof follows the text | sync script: `STALE` |
| `tlapm --cleanfp --strict`; read only the final count and exit status | fingerprints hide stale results; a backend's failure line is noise when another closed it | run script exit status |
| Flip one hypothesis and watch the proof fail before generating results | a proof that survives proves the wrong thing | scratch run, not committed |
| Fairness as `WF`/`SF` on actions of `Next`, named for whose obligation it is, a row that drops each, a `NoBehaviour` row that is violated | a state condition is not machine-closed and can leave an empty spec under which everything holds | liveness rows |
| A well-formedness assumption on constants is a named `ASSUME` in the module; a space-cutting bound stays in the run script | TLC checks the first against the config and the proof cites it; the second would narrow the theorem for nothing | theorem statement; the prover ignores an unnamed `ASSUME` |
| Prove an unquantified leads-to by a measure, one WF1 step that lowers it, and `Nat` induction over a hidden `G(n)` | the measure step needs `ENABLED <<A>>_vars`, and `G` must stay hidden outside `PTL` steps | the proof shape in [proof-style.md](references/proof-style.md) |
| `-deadlock` on by default; audit it separately | most modules have always-enabled actions, so a stall is a livelock and only a leads-to sees it | a deadlock audit over every `-deadlock` script |
| Pin the checker and the prover by digest; print them in every results file; refuse an unpinned binary without an explicit override | a different build is a different trusted-base item | wrapper script, sync script |
| Keep untranslated terms (`ENABLED`, `\cdot`, temporal formulas) behind hidden definitions in SMT, Zenon and Isabelle steps; expand them only `BY ExpandENABLED` where proved or in `PTL` steps | the prover abstracts them to a constant that forgets bound variables | the scan described in [prover-habits.md](references/prover-habits.md) |
| Expand no definition at an argument that names one of its bound variables | the expansion prints, and is named, as another term | the same scan |

Each row's rationale, with the anti-pattern it prevents, in
[anti-patterns.md](references/anti-patterns.md).

## Rationalizations to reject

| Excuse | Reality |
|--------|---------|
| "TLC passed at the constants we care about, so it holds" | TLC at constants is non-vacuity and discrimination. It says a bad state is reachable under each mutation and no bad state under none, at those constants. The universal claim is the prover's, and the word for TLC's result is "checked". |
| "The proof went through, so the mechanism is safe" | A proof is of the module under its hypotheses and its prover. It is not a claim about the code, the deployment, or the constants' meaning. Say which hypotheses, and keep the refinement gap on the record. |
| "The invariant is obviously inductive, write the Next lemma" | Decide the inductive invariant first and write it down. Half the modules need a strengthening, and the step that fails will tell you only that something is missing, not what. |
| "Assume `Mut = "none"` for every theorem, it's simpler" | Each theorem's weakest hypothesis is what documents the property's sensitivity, and writing them has corrected the design record's "Breaks under" column several times. `Mut = "none"` is for `SafeAlways` only. |
| "No need for the mutation rows now that the invariant is proved" | The prover cannot show a mutation reaches a bad state; that is existential and stays with TLC. A proof without mutation rows cannot show the property discriminates anything. |
| "I'll fix up the results file by hand, the change is tiny" | The results file is the evidence. A hand edit is the one change it never takes. Regenerate, or the digest line is a lie. |
| "The module needs one small edit; the proof still goes through" | A module cited by digest is frozen. Write the successor beside it, copy the proof, point `EXTENDS` at the successor, re-prove, and commit both results files together. |
| "Simulation at large constants found nothing, so it holds there too" | "No error sampled" is evidence of a different kind and is never cited as a check. Record it with depth, trace count and seed and say what it is. |
| "The proof compiled, skip the flip test" | A proof that still proves with a hypothesis flipped to the mutation it excludes is proving something the mutation does not break. It takes one scratch run. |
| "The property holds in every state by definition, no need to state it as a property" | Then prove it as a state lemma and lift it with `PTL`. An `ENABLED` invariant proved this way is the strongest form a "the mechanism never gates this" claim can take. |
| "A longer timeout will get the last obligation through" | It rarely does. Split the step by field or by action, give the case split explicitly ("an old member, or the new one"), or name the parts of a large `LET`. Each failure so far was a real gap or an oversized step. |
| "`-deadlock` is on, so a stall would have been caught" | Modules with always-enabled actions never deadlock; a Thinker stalled for good is a livelock, which only a leads-to property sees. Audit the flag and state liveness where the design claims progress. |
