A method for a family of diagrams that are generated from code, sized for posters, adaptive to light and dark, and
held to the same standard of evidence as the corpus they draw. It is distilled from the TOPAK diagram family
(`diagrams/topak/`, 52 diagrams by 2026.11.10), whose rules are in `diagrams/topak/src/AUTHORING.md`.

**Core principle: a diagram is a second compilation of the records, and the compiler is strict where prose is
lenient.** Prose tolerates a stale sentence, a miscounted list, a drifted quotation, a section one record has and
its siblings lack. A generator that must set every table cell, cite a section for every card, choose one of a fixed
set of status pills, and regenerate byte for byte does not. That is why the family is worth generating even when no
person looks at a picture: drawing the ten records of one overlay surfaced eighteen findings, thirteen of which
needed only the attempt to draw ([rationale](references/rationale.md)). A diagram still decides nothing: where a
diagram and a record disagree, the record wins.

Scripts live in `scripts/` next to this file and run with `uv` (each carries inline script metadata and needs no
packages). From the repository root, `SK=skills/generating-corpus-diagrams/skills/generating-corpus-diagrams`.

## When to Use

- Drawing a new diagram of a record, a group of records, a module's evidence, or the corpus's structure
- Amending a diagram because a record was revised, a batch ratified, a results file or pin replaced
- Reviewing a diagram, yours or a drawing agent's, against its records and in both themes
- Running several drawing agents at once, one diagram each
- Regenerating the whole family after a batch, and triaging what changed
- Diagnosing why a diagram nobody touched changed when regenerated

## When NOT to Use

- **A one-off sketch for a conversation.** Use an Artifact or a quick inline SVG; the family's rules cost time
  that only pays back for a diagram that is kept and regenerated.
- **Deciding anything.** A diagram is derived. A finding made while drawing goes to the custodian as a lead; the
  record is changed by its own process, never by the diagram.
- **Charts of data.** The library draws cards, tables, regions and arrows, not axes. Use a charting tool.

## The workflow

1. **Choose and scope.** One diagram answers one question about one record or a tight group (a record and the one
   it revises; two records that share a mechanism). Pick the group letter by what is drawn; take the next free id
   with `uv run $SK/scripts/new_diagram.py --free`.
2. **Read the records whole**, as revised, with their History rows, and every module or results file the diagram
   will cite. Note each table: it will be drawn whole.
3. **Scaffold**: `uv run $SK/scripts/new_diagram.py <ID> <slug> "<title>"`. The module builds as it stands, with a
   status strip, a band of cards and a table to replace.
4. **Draw**, by the [content rules](references/content-rules.md) and the [drawing guide](references/drawing.md):
   status strip first; then the picture of the mechanism; then each record section as bands of cards; every table
   whole; ratification conditions item by item with met or not met; options and consequences. Cite a section on
   every card. List every source in `sources`. Set the footer's `state=` when drawing after the family's cut.
5. **Generate**: `uv run --no-project --python 3.9 python diagrams/gen-topak-family.py <ID>` (the pinned
   interpreter; see [the regression check](#the-regression-check)). It must print the SVG path and **no WARNING
   lines**.
6. **Look at it**, both themes, whole and cropped at reading zoom: `uv run $SK/scripts/render.py <ID>`, then
   `--needle "<text>" --h 900 --width 1800` for each region. Read the PNGs. The overlap checker sees text on text;
   only looking sees an arrow through a card, a label on a line, a card too short, dark-theme contrast
   ([review](references/review.md)).
7. **Verify the content** against the records: counts, quotations, status words, every claim the diagram makes that
   a record does not (label it as the diagram's, or remove it), every number a record does not state (label it
   illustrative).
8. **Run the regression check**: `uv run $SK/scripts/regen_check.py --expect <ID>`. Only the new or declared
   diagrams may change. Anything else is a finding to report, not to fix in passing.
9. **Index it**: a row in the family README's table under its group, and a dated paragraph saying what was drawn,
   against what state, and what was deliberately not amended.
10. **Report the findings** the drawing surfaced, each with where, to the custodian. Do not edit records to match
    the diagram.

## Drawing in parallel

Several diagrams of related records can be drawn at once, one agent each, with fresh context. That is faster, and
each agent is a cold reader of its records, which is where many findings come from.

- Copy `assets/agent-brief.md`, fill in the paths, the state constant and the records' status markers, and give
  each agent its own assignment: id, slug, working title, the records and modules to read, what to cover.
- Each agent may write only its own module and SVG. Add any shared constant (a footer state) to the library
  yourself, before launching.
- **Their reports are leads.** Check every inconsistency an agent reports against the files before passing it on;
  some will not hold up. Then render and look at every diagram yourself, at least whole and in the regions the
  agent flagged, and run the regression check over the whole family.

## The regression check

The family is deterministic: a diagram whose inputs have not moved regenerates byte for byte. So
`regen_check.py` regenerates everything and sorts every changed file into new, expected (declared with `--expect`)
and **unexpected**, which is a finding: a record, results file or pin a diagram reads has moved, or the library
changed. `--restore` writes back the unexpected files' previous bytes after reporting them.

**The interpreter is part of the input.** Python 3.12 made `sum()` over floats compensated, so the same generator
writes different coordinates from 3.12 on. The check runs the generator with `uv run --no-project --python 3.9`
(the interpreter TOPAK's family was generated with). Generate by hand under the same interpreter, or the whole
family changes. Moving the pin is a whole-family regeneration, committed as such.

## Quick reference

| Task | Command or rule |
|---|---|
| Next free ids | `uv run $SK/scripts/new_diagram.py --free` |
| New diagram module | `uv run $SK/scripts/new_diagram.py C12 slug "Title"` (`--dry-run` to print) |
| Generate one | `uv run --no-project --python 3.9 python diagrams/gen-topak-family.py C12` |
| Render both themes | `uv run $SK/scripts/render.py C12` (PNGs under `$TMPDIR/diagram-render/C12/`) |
| Crop at a text | `uv run $SK/scripts/render.py C12 --needle "Status" --h 900 --width 1800` |
| Crop by coordinates | `--y 2200 --h 900 --x 0 --w 1700` (SVG units) |
| Whole-family check | `uv run $SK/scripts/regen_check.py [--expect C12] [--restore]` |
| Read a regeneration diff | `git diff --word-diff=porcelain <svg> \| grep -E '^[-+][^-+]' \| sed 's/<[^>]*>//g'` |
| Status words | *checked* (TLC, gates), *proved* (a proof module), *certified* (every obligation accounted for, LS4 named), *proved in Lean*; never of running code |
| Equal-height row | measure every card with `draw=False`, draw all at the max (`row_cards`) |
| A claim no record makes | head its column or card as the diagram's own |
| A number no record states | label it illustrative |

## Rationalizations to reject

| Rationalization | Reality |
|---|---|
| "The table is long; the important rows are enough." | Full tables are what make drawing an audit. A summary skips exactly the row that disagrees with the prose. |
| "No warnings, so it is done." | The checker sees text overlapping text, and not a card that outgrows a row height computed over others, an arrow through a card, or dark-theme contrast. Look at it. |
| "The agent rendered it and said it looks fine." | Its report is a lead. Look at it yourself, and check every inconsistency it reported against the files. |
| "Three other diagrams changed on regeneration; I'll commit them too." | An unexpected change is a finding: a record or result moved under a diagram. Report it; amend on purpose, with its own note, or restore. |
| "Regenerated under a newer Python, everything shifted slightly; harmless." | It makes every diff noise and hides the real findings. Pin the interpreter. |
| "The diagram should say the record's claim more clearly, so I'll improve it." | A diagram says what the record says. If the record is unclear, that is a finding for the record. |
| "An example with round numbers makes the point." | Then say they are illustrative, on the diagram. Unlabelled, they read as the record's. |
| "The record is Proposed, but the design is obviously settled." | Status is shown, not implied. Proposed is drawn Proposed until it is ratified. |
| "I'll read the newest results file so the diagram stays current." | Then any new results file of another kind changes the diagram silently. Name the file, or select by what the diagram draws. |
