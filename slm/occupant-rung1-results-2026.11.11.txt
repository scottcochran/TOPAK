## Findings
  - Same digest. ADR-0036 R1 has elevation name the same profile digest at a higher rung, one change at a time. The host-run rung-0 profile and the rung-1 profile are different files (image, launch, channel, P1, P2, P3), so the step from one to the other changes clause verdicts and the rung together. The profile's _ladder note glosses this.
  - Resource limits. topak-contain's DockerLaunch applies no --memory, --cpus or environment, so the rung-1 profile lists none and slm/serve/run.sh's 2 GB / 4 CPU ceilings do not apply under the launcher. Unknown keys in a profile's launch part are ignored silently (no deny_unknown_fields).
  - §4 skipped. ADR-0036 §4 and §7 name slm/serve's Python image with P3 fail. This run used a P3-passing image instead, by the custodian's choice (2026.11.11); §7 as written is therefore not what this run shows.
  - Stale text under mechanism/. GAPS-AND-ASSUMPTIONS.md G1 ('the only image is P3-fail') and the line saying every lease is rung 0 no longer describe what the reference can launch. Editing them is a mechanism/ change.
  - Image identity. The profile's image is docker image inspect's Id. Under Docker Desktop's containerd store that is the image index digest, and by default the index carries a build-provenance attestation that changes on every build, so a rebuild of the same binary was a new profile. The image is built with --provenance=false, which made the Id stable across rebuilds here; it is still not a reproducible-build claim.
